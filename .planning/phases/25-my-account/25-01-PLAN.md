<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → server action | requestEmailChange/deleteAccount inputs cross here (only `newEmailRaw` is untrusted; userId is server-derived) |
| email inbox → verify GET route | the verification token arrives via an unauthenticated URL click (possibly a different device) |
| DB (verification/user) | token store + identity of record |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01-A | Tampering | email-change token | mitigate | Token = crypto.randomUUID() (~122 bits), stored server-side in verification.value; never derived from client input |
| T-25-01-B | Tampering | verify route (replay) | mitigate | verification row deleted immediately on success; a second click finds no row → ?verified=expired |
| T-25-01-C | Tampering | verify route (expiry) | mitigate | `match.expiresAt < new Date()` checked before UPDATE; TOKEN_TTL_MS = 24h |
| T-25-01-D | Tampering | requestEmailChange (identifier collision) | mitigate | Deterministic identifier `change-email:{userId}`; delete-then-insert → exactly one pending row per user |
| T-25-01-E | Spoofing/Info Disclosure | verify route (uniqueness race) | mitigate | Race re-check `clash.id !== userId` before UPDATE; both sides lowercased (Pitfall 5) |
| T-25-01-F | Tampering | verify route (open redirect) | mitigate | Redirect target hardcoded to `request.nextUrl.origin` + fixed path; no callbackURL param exists |
| T-25-01-G | Elevation/Info Disclosure | actions + verify route (IDOR) | mitigate | Actions re-derive userId from getSession; verify route resolves userId only from the server-stored token→identifier mapping, never client input |
| T-25-01-H | Denial of Service | requestEmailChange (email-send abuse) | mitigate | createRateLimiter 5 req/hr/user keyed by userId; over-limit returns error before any send |
| T-25-01-I | Info Disclosure | email enumeration via "already in use" | accept | Deliberate honest error for a low-stakes personal app (UI-SPEC contract); documented tradeoff vs better-auth's anti-enumeration default |
| T-25-01-J | Tampering | deleteAccount (authz) | mitigate | `db.delete(user).where(eq(user.id, userId))` with session-derived userId only; no client-supplied id, no GET |
| T-25-01-SC | Tampering | dependency supply chain | accept | Zero new packages this phase (RESEARCH §Package Legitimacy Audit N/A); no install task |
</threat_model>
