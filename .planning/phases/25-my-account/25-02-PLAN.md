<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client form → authClient.changePassword | current/new password values cross to better-auth's /change-password endpoint |
| ChangePasswordCard → AccountDirtyProvider | only a derived boolean crosses (never the typed text) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-02-A | Session Management | password change (session fixation) | mitigate | `revokeOtherSessions:true` ends all other sessions and issues a fresh token for this device (better-auth verified behavior) |
| T-25-02-B | Info Disclosure | dirty-form guard (leaking typed password) | mitigate | AccountDirtyProvider stores ONLY a boolean; the 25-04 dialog copy is generic ("Your password changes haven't been saved."), never echoes typed text |
| T-25-02-C | Spoofing | current-password verification | mitigate | changePassword server-verifies currentPassword (INVALID_PASSWORD); client maps by .code, never bypasses; no client-side password compare |
| T-25-02-D | Info Disclosure | password fields in DOM/logs | mitigate | type=password inputs; values never logged, never stored outside the single changePassword call |
</threat_model>
