<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /account (searchParams) | untrusted `?verified` query param crosses here |
| client → deleteAccount server action | delete request crosses (userId server-derived, not client-supplied) |
| (protected)/layout.tsx | the session gate every account request passes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-04-A | Tampering (CSRF) | delete-account | mitigate | deleteAccount is a Next Server Action (same-origin action-id + framework CSRF protection, POST-only) re-deriving userId from the session; no GET, no client id |
| T-25-04-B | Tampering | ?verified param injection | mitigate | page.tsx allow-lists to exactly "success"/"expired"/null (habitat guard pattern); raw param never rendered |
| T-25-04-C | Info Disclosure | back-guard dialog (typed password leak) | mitigate | AccountBack reads only the passwordDirty boolean; dialog copy is generic, never echoes field text (T-25-02-B) |
| T-25-04-D | Session Management | post-delete session validity | mitigate | deleteAccount cascade-deletes the session row + auth.api.signOut clears the cookie; client redirects /login (D-14) |
| T-25-04-E | Access Control | unauthenticated /account | mitigate | Inherits (protected)/layout.tsx redirect + defensive `if(!session) return null` |
</threat_model>
