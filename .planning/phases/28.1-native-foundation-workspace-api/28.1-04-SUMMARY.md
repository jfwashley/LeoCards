## Decisions Made

- `saveCardCore`'s ownership check selects `{ id, userId }` (not just `id`) and requires both row presence and an exact `userId` match — the combined-WHERE clause remains the real, production-effective defense (a foreign-owner row can never actually be returned by a live database), but the application-level re-check is what keeps `deck-actions.test.ts`'s existing mock-based "throws Forbidden if deck does not belong to user" test passing without editing that file, since the mock returns a queued row irrespective of the WHERE clause's actual conditions. Both a missing row and a mismatched owner produce the identical `{ ok: false, code: "forbidden" }`, so T-12-08's no-existence-leak guarantee is unaffected either way.
- Did not import `LANGUAGE_LABELS` into `deck-actions.ts` despite the plan's literal action text saying to — after correct delegation, no code in that file computes a deck name anymore (`createDeckCore`'s `result.data.name` already carries it), so the import would be dead code. Biome's `noUnusedImports` rule flagged exactly this ("the result of an incomplete refactoring") when the import was first added; removing it restores a fully clean scoped Biome pass while the underlying "one map, one source of truth" goal remains satisfied — there is exactly one `LANGUAGE_LABELS` declaration in the whole codebase now, in `src/lib/core/decks.ts`.
- `NAT-02` traceability intentionally left unmarked in REQUIREMENTS.md this plan, despite this plan's own frontmatter listing it — it spans six contributing plans within Phase 28.1 (03/04/05/06/07/09), and only the last (28.1-09) should flip the checkbox, per the precedent 28.1-01 established and 28.1-02/03 both followed.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] saveCardCore's pure presence-only ownership check failed the unedited deck-actions.test.ts suite**
- **Found during:** Task 2, running the mandatory `npx vitest run src/lib/deck-actions.test.ts` regression gate before committing.
- **Issue:** Task 1's `saveCardCore` implemented the ownership gate exactly like the `saveImageCards`/`getSameLanguageDeckBackWords` precedent — `select({ id: decks.id })` with the combined-WHERE clause, then a pure `if (!deckRows[0])` presence check. This is correct against a real database (the WHERE clause itself guarantees a foreign-owner row can never be returned), but `deck-actions.test.ts`'s pre-existing "throws Forbidden if deck does not belong to user" test mocks `selectChain.where` to resolve a row shaped `{ id: FAKE_DECK_ID, userId: "other-user" }` regardless of what conditions were passed to `.where()` — the mock has no SQL semantics. Since the new code never reads the row's `userId` field, it treated that mocked row as "owned" and let the write proceed, and the test failed asserting no error was thrown.
- **Fix:** Changed the query to select `{ id: decks.id, userId: decks.userId }` and check `!deckRow || deckRow.userId !== userId` before treating the deck as owned. This is additional defense-in-depth on top of the (unchanged) combined-WHERE clause, not a replacement for it — both a missing row and an owner mismatch still return the identical `"forbidden"` code, preserving T-12-08.
- **Files modified:** `src/lib/core/decks.ts`, `src/lib/core/decks.test.ts` (updated the three "owned deck" mocks to include `userId`, added a new dedicated test for the foreign-owner-row case).
- **Verification:** `npx vitest run src/lib/deck-actions.test.ts src/lib/core/decks.test.ts` — 46/46 passing; full `npx vitest run` afterwards showed 0 failures.
- **Committed in:** `b7ae9cf` (separate fix commit, landing between Task 1 and Task 2's commits since Task 1 was already committed when this was discovered).
