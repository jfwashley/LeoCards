Working tree was already correct (the files were genuinely gone from disk); only the git object graph at `HEAD` still contained the phantom old files (confirmed via `git show HEAD:src/lib/study-engine.ts` succeeding when it should have failed).
- **Fix:** Committed the already-staged deletion as a small, clearly-labeled follow-up (`d057dde`), explicitly listing both old paths in its pathspec.
- **Files modified:** `src/lib/study-engine.ts`, `src/lib/study-engine.test.ts` (deletion only, zero content change — the deletion was already staged from the original `git mv`)
- **Verification:** Post-fix, `git show HEAD:src/lib/study-engine.ts` fails (as expected); `git status --short` clean; `git diff -M HEAD~2 HEAD --stat -- src/lib/study-engine.ts packages/domain/src/study/study-engine.ts` now correctly shows the rename with exactly 1 line changed; `git log --follow` traces the full history back to the original `feat(03-01)` implementation commit.
