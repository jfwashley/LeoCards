- **DR-06 (RESEARCH Open Question 3) — a MINIMAL, hand-authored Expo workspace member, not
  `npx create-expo-app`'s template.** RESEARCH is right that a bare stub cannot prove Metro
  resolves the shared package, and that proving it is worth doing now. But `create-expo-app`'s
  default output is a full expo-router navigation template with tab screens, assets and example
  code — and the navigation shell is explicitly 28.2's deliverable (D-02, and CONTEXT's Deferred
  list). Committing a generated shell would force 28.2 to either inherit or delete decisions it
  owns. A five-file hand-authored member proves exactly what 28.1 needs (workspace membership +
  Metro cross-boundary resolution + a buildable RN graph) and pre-empts nothing.

- **The `mobile` workspaces entry is added HERE, not in plan 28.1-01.** npm errors on a literal
  workspace entry pointing at a directory that does not exist, so `"workspaces"` was
  `["packages/*"]` through Waves 1-5. It becomes `["mobile", "packages/*"]` in this plan, in the
  same change that creates the directory.

- **Expo/RN versions are resolved at execution time, never from this document.** RESEARCH
  demonstrated its own staleness live: web search returned SDK 54/55 while the registry returned
  `expo@57.0.9` the same session. Run `npm view expo dist-tags` immediately before scaffolding and
  use what it returns. This plan names no SDK number on purpose.

- **`mobile/` is excluded from the web app's tooling, not folded into it.** `tsconfig.json`
  already excludes it and `biome.json` already negates `mobile/**` (both landed pre-emptively in
  plan 28.1-01). `mobile/` gets its own tsconfig extending `expo/tsconfig.base`. Do not add
  `mobile/**` to this project's Biome ruleset — RN/Expo JSX conventions differ and Expo's own
  toolchain owns that surface.
