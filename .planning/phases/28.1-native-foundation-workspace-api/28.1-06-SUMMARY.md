## Accomplishments

- `src/lib/core/study.ts` created: `loadStudySessionCore(input: { userId: UserId; deckId: string; now: Date }): Promise<CoreResult<StudySessionResponse>>` — validates `deckId` presence, runs a combined-WHERE ownership gate (`and(eq(decks.id, deckId), eq(decks.userId, userId))`) BEFORE any card read, reuses `getStudyCards`'s existing pause-exclusion filter unchanged, assembles the session via the real `assembleSession` engine, and serialises `cooldownUntil`/`createdAt` to ISO strings for the wire. Never resolves a session, reads cookies, or revalidates a path — those stay at each entry point's boundary.
- `src/lib/core/study.test.ts` — 7 tests covering every `<behavior>` bullet: empty/missing `deckId` → invalid (never queries), no ownership row → forbidden (asserts `getStudyCards` is never called — the access-control ordering guarantee), owned deck → `ok:true` with `deckId` echoed and real-engine-assembled cards, empty `assembleSession` output → `ok:true` with `cards: []` (not an error), and ISO-string/`null` serialisation for `cooldownUntil` (using a past, already-due cooldown fixture so the card is still included in the session) plus `createdAt`.
- `src/app/api/study/route.ts` created — `GET /api/study`, sitting beside the untouched `src/app/api/study/complete/route.ts`: raw `auth.api.getSession` (cached-cookie fast path) → 401 → 60/min rate limiter → 429 with `Retry-After` → `readQaTimeOffset()`-shifted `now` → `loadStudySessionCore` → `CORE_ERROR_STATUS` mapping (400 invalid, 403 forbidden) → raw `Response.json(result.data)` with no wrapper key on success.
- `src/app/api/study/route.test.ts` — 7 tests: 401, 429 with a numeric `Retry-After` header, 400 on a missing `?deck=`, 403 with no card data leaked, 200 happy path with no wrapper key, 200 + `cards: []` on an empty session (never a 404, never a redirect), and QA-offset propagation into the core's `now` input.
- `src/app/(protected)/study/page.tsx` rewritten to delegate: keeps the missing-deck redirect and the cached `getSession()` RSC accessor exactly as before, replaces the inline ownership-select/`getStudyCards`/`assembleSession` composition with one `loadStudySessionCore` call, keeps both the not-ok redirect and the empty-session `` redirect(`/dashboard?deck=${deckId}`) `` byte-identical, and revives the wire cards' ISO strings back into real `Date` objects before handing them to `StudySession`'s unchanged `initialCards: SessionCard[]` prop. All now-unused imports (`and`, `eq`, `db`, `decks`, `DeckId`, `getStudyCards`, `CardForSession`, `assembleSession`) removed.

## Decisions Made

- `loadStudySessionCore`'s ownership check stays presence-only (`{ id: decks.id }`, no `userId` re-selection), matching the plan's literal instruction and the original page's exact query — unlike `saveCardCore`'s (28.1-04) defense-in-depth double-check, which was only needed to satisfy a pre-existing, unedited test file's mock. `study.test.ts` is new and fully under this plan's control, so its queued mock return values already correctly model real combined-WHERE filtering.
- No attempt was made to introspect the drizzle SQL tree passed to `.where()` to prove both conditions are present at runtime in a test — no precedent for this exists anywhere in the codebase, and mocks have no SQL semantics to assert against (per 28.1-04-SUMMARY.md's finding). The combined-WHERE shape is covered by this plan's own acceptance-criteria grep (`eq(decks.userId`: 1) instead.
- The page's ISO-to-Date revival maps each wire card field explicitly (`cooldownUntil: c.cooldownUntil ? new Date(c.cooldownUntil) : null`, `createdAt: new Date(c.createdAt)`) rather than introducing a shared revival helper — this is a one-call-site, one-time concern, and a helper would add indirection without removing any duplication (no second revival site exists anywhere in this codebase yet).
