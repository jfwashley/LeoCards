into one core function, expose it as `GET /api/study?deck=<id>`, and make the existing RSC study
page delegate to it.

web and native "by construction"; `assembleSession` already lives in the shared package after
plan 28.1-02, and this plan makes the surrounding composition (which cards get fetched, how they
map to session inputs, what an empty session means) single-sourced too.

Output: `src/lib/core/study.ts`, `GET /api/study` with tests, and a delegating RSC page.
</objective>

<planner_decisions>
- **DR-07 (naming) — `GET /api/study?deck=<id>`.** The deck id travels as a query parameter, not
  a path segment, matching the web route it mirrors (`/study?deck=<id>`) and the existing
  `/api/dashboard?deck=` shape from plan 28.1-05. `POST /api/study/complete` already exists at
  the sibling path and is untouched — the two coexist cleanly because they use different methods
  and different path depths.

- **Empty session returns 200 with `cards: []`, never a redirect.** The web page redirects to
  `/dashboard?deck=<id>` when `assembleSession` yields nothing; an HTTP redirect is meaningless
  to a native client, which must decide its own empty-state UI (28.3's job). The contract
  declares this explicitly.

- **Missing `deck` parameter returns 400 `{ error: "invalid" }`.** The web page redirects to
  `/dashboard` in that case. Same reasoning as above: the endpoint reports the input problem and
  lets the client route.

- **Auth: cached fast path**, matching `/api/dashboard` and all four existing route handlers.
  This is a read; there is nothing revocation-sensitive about it.

- **Rate limit: 60 requests/minute/user**, matching `/api/dashboard`. A study session load happens
  once per session start plus retries; 60/min leaves ample headroom while capping the polling
  pattern RESEARCH flags as this phase's DoS threat.
</planner_decisions>
