Time-shift semantics (15-01-SUMMARY authoritative): offsetMs ms added to new Date() at /api/study/complete, /api/habitat, /api/debug/state. Positive = future. Apply the shift BEFORE the assertion read so quality/isDecaying/minutesSinceActivity reflect the simulated future (RESEARCH pitfall 5). Range ≤30 days.

Manifest schema (RESEARCH §6 — proposed; finalize in qa-03):
  { schemaVersion, runId, createdAt, phase, baseUrl, user:{ email, password, sessionToken }, deck:{ id, language }, cards:[{ id, front, back, gradeCommitId, expectedMasteryRound, expectedDirection, cooldownUntilExpected, expectedState:"cooling"|"due" }], resumeAfter, completedPhases:[] }
  Resume logic: read manifest → check resumeAfter <= now (or apply time-shift to satisfy it) → re-signIn → readState → for each card compare masteryRound to expected and cooldownUntil vs cooldownUntilExpected (now >= expected ⇒ due [cooldownUntil null or <= now]; else cooling) → assert dueCards.length matches expected.

Decay rules (src/lib/habitat-engine.ts — VERIFIED): GRACE_PERIOD_MS = 2 days; DECAY_RATE_PER_DAY = 0.05. Within grace quality=1.0; past grace quality = 1 - daysPastGrace*0.05. So +4 days ⇒ 2 days past grace ⇒ quality≈0.90, isDecaying true.

Pause interaction (RESEARCH §7 — VERIFIED): paused cards (pausedAt non-null) are filtered out of study sessions and never receive SRS cooldowns; pausing does NOT change lastActivityAt, so habitat still decays on elapsed time. These routes are NOT time-shifted (they record wall-clock pausedAt the harness controls) — so for the pause assertion, the paused card's masteryRound + cooldownUntil must be UNCHANGED after a +4-day shift, while real.isDecaying flips true.

Script skeleton (PATTERNS.md): shebang, env guard (DATABASE_URL + DEBUG_CHEAT_SECRET) + process.exit(1) before I/O, BASE_URL default, `[QAJ-NN] PASS`/`process.exit(0)`, try/catch → `[QAJ-NN] FAIL` + exit 1. qa-03 manifest write uses node:fs/promises atomic write (`writeFile` .tmp then `rename`) — but prefer the qa-lib writeManifest/readManifest helpers.
