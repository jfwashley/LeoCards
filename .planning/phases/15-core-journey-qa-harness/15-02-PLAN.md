## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| qa-lib.mjs → DATABASE_URL | direct DB write access for test-data provisioning |
| qa-lib.mjs → app HTTP API | holds a real session cookie; acts as an authenticated user |
| qa-lib.mjs logs → operator console | risk of leaking session token / password / secret |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-06 | Information Disclosure | session token / password / DEBUG_CHEAT_SECRET in logs | mitigate | qa-lib helpers MUST never `console.log` the session token, password, or secret; log only emails, ids, masteryRound, pass/fail (RESEARCH Security Domain) |
| T-15-07 | Tampering | provisioning writes to real prod DB | mitigate | all users restricted to the `@test.local` domain so `cleanup-test-users.mjs` reaps them (QAJ-06); a non-test domain is never minted |
| T-15-08 | Spoofing | accidental real-user mutation | mitigate | provisioning only ever INSERTs new test rows keyed to a freshly-created test user; never UPDATEs/DELETEs arbitrary users |
| T-15-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages — `@neondatabase/serverless` + `drizzle-orm` already in package.json (RESEARCH); no install task |
</threat_model>
