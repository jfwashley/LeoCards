**Fix A (SEC-04 — N+1 query in markMilestonesSeen):** Replace the for-loop with individual INSERTs (lines 34-43) with a single batch INSERT:

```typescript
export async function markMilestonesSeen(
  userId: string,
  prevLevel: number,
  newLevel: number,
): Promise<void> {
  if (newLevel <= prevLevel) return;

  // Build all milestone rows at once
  const rows = [];
  for (let lvl = prevLevel + 1; lvl <= newLevel; lvl++) {
    rows.push({
      id: crypto.randomUUID(),
      userId,
      milestone: `level-${lvl}`,
    });
  }

  // Single batch INSERT with ON CONFLICT DO NOTHING (idempotent, D-06)
  await db.insert(milestones_seen).values(rows).onConflictDoNothing();
}
```

This replaces N separate round-trips with a single INSERT statement.

**Fix B (SEC-05 — floating-point boundary in minutesSinceActivity):** In `computeHabitatState` (src/lib/habitat-engine.ts), change line 202 from:

```typescript
const minutesSinceActivity =
  lastActivityAt !== null
    ? (now.getTime() - lastActivityAt.getTime()) / (60 * 1000)
    : null;
```

to:

```typescript
const minutesSinceActivity =
  lastActivityAt !== null
    ? Math.floor((now.getTime() - lastActivityAt.getTime()) / (60 * 1000))
    : null;
```

This prevents float division from producing values like 59.99999 that could cause the excited mood check (`<= 60`) to behave unexpectedly at the boundary.

**Fix A (SEC-06 — language validation in createDeck):** At the top of `createDeck` in deck-actions.ts, before the session check, add an allow-list validation:

```typescript
const ALLOWED_LANGUAGES = new Set(["fr", "es", "en"]);
```

Move this constant to module scope (near LANGUAGE_LABELS). Then at the start of `createDeck`, add:

```typescript
if (!ALLOWED_LANGUAGES.has(language)) {
  throw new Error("Invalid language");
}
```

This rejects any language string not in the allowed set. The LANGUAGE_LABELS map already has the same three keys, but it silently falls back to the raw string for unknown languages — that fallback is the vulnerability.

**Fix B (SEC-07 — unvalidated celebrate param):** In dashboard/page.tsx, replace line 60-62:

```typescript
const celebratingLevel = params.celebrate
  ? parseInt(params.celebrate, 10)
  : null;
```

with:

```typescript
const rawCelebrate = params.celebrate ? parseInt(params.celebrate, 10) : null;
const celebratingLevel =
  rawCelebrate !== null && !Number.isNaN(rawCelebrate)
    ? Math.max(1, Math.min(10, rawCelebrate))
    : null;
```

This clamps the celebrate parameter to the valid level range 1-10 and handles NaN from non-numeric strings.
