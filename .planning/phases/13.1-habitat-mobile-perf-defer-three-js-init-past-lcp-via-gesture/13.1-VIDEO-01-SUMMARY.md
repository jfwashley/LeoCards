# Phase 13.1 Plan VIDEO-01: Habitat Video Capture Speed-Rework Summary

Replaced the 60×-too-slow per-frame Playwright canvas screenshot loop with
real-time in-page MediaRecorder capture of the live WebGL canvas — ~10.8
min/clip → ~6s of actual recording per clip — then rendered all 36 level×mood
ambient loop clips as webm (VP9) + mp4 (H.264).

## New Capture Architecture (MediaRecorder)

The old spec called `page.locator(canvas).screenshot()` 120×/clip — 120
Playwright↔browser round-trips → ~10.8 min/clip → ~6.5h for 36 clips. Unviable.

The new spec records the canvas **entirely in the browser** via `page.evaluate`:

1. Navigate `/habitat?snapshot=true&devLevel=N&devMood=M&capture=video`, wait
   for `canvas[data-testid="habitat-3d-canvas"][data-ready="true"]`, lock theta
   to π/4 via `window.__habitatSetTheta` (the flattering fixed angle).
2. In-page: `canvas.captureStream(30)` → `new MediaRecorder(stream, {mimeType:
   'video/webm;codecs=vp9', videoBitsPerSecond: 2_500_000})`; collect chunks on
   `ondataavailable` (timeslice 250ms), `rec.start()`, record 5500 ms,
   `rec.stop()`, build `Blob` on `onstop`, `FileReader.readAsDataURL` → resolve
   base64. Falls back to vp8/default mime if vp9 unsupported.
3. Decode base64 → write `e2e/scripts/.tmp/clips/l{N}-{mood}.raw.webm`.
   Asserts raw > 8 KB (cheap black/empty guard).

The WebGL canvas is actively rendering in `?capture=video` mode (RAF ambient
loop ticks `updateWorld` with `reducedMotion:false`), so `captureStream(30)`
pulls live frames — no black-frame fallback was needed.

## Why (60× speedup)

| Metric | Old (per-frame screenshot) | New (MediaRecorder) |
|---|---|---|
| Per-clip capture | ~10.8 min | ~6s recording (~16.3s incl. nav/signup) |
| Full 36-clip batch | ~6.5 h (projected) | 9.7 min capture + ~4.5 min encode |

## Orchestrator Change

Input is now ONE `*.raw.webm` per clip (not a frame dir). Per clip, ffmpeg:
(a) normalizes fps + trims to a clean 5s, (b) applies the SAME validated
tail→head `xfade` (0.5s) seamless loop → 4.5s, (c) writes final webm + mp4.
Kept `--only=<clip>` scoping. Added a non-black mid-frame check (extract frame
at t=2s; fail if < 4 KB). Size bands tightened to webm ≤ 500 KB / mp4 ≤ 600 KB.

### Encode settings (unchanged from the validated baseline)

- **webm:** `libvpx-vp9 -b:v 0 -crf 34 -row-mt 1 -pix_fmt yuv420p`, 30fps, no audio.
- **mp4:** `libx264 -profile:v high -crf 28 -preset slow -pix_fmt yuv420p -movflags +faststart`, 30fps, no audio.
- **Loop filter:** `fps=30,format=yuv420p,trim=0:5,split[a][b];[a][b]xfade=transition=fade:duration=0.5:offset=4.5,trim=0:4.5`.

## Consumption Contract (for the next task)

- **Filenames:** `public/habitat/clips/l{N}-{mood}.{webm,mp4}` where
  `N ∈ 1..9`, `mood ∈ {excited, happy, neutral, sad}`.
- **Poster:** `public/habitat/hero-l{N}.webp` (from Plan 04) as the `poster`.
- **Recommended element** (webm-first, mp4 fallback, autoplay-safe):

```html
<video autoPlay muted loop playsInline preload="auto"
       poster="/habitat/hero-l{N}.webp">
  <source src="/habitat/clips/l{N}-{mood}.webm" type="video/webm" />
  <source src="/habitat/clips/l{N}-{mood}.mp4"  type="video/mp4"  />
</video>
```

`muted` + `playsInline` are required for mobile autoplay. Clips are 4.5s
seamless loops; `loop` plays them indefinitely with a masked seam.

## Deviations from Plan

- **[Rule 1 - Fix] xfade input adaptation.** The old filter assumed a PNG frame
  glob input (`-framerate -i frames%04d.png`). The new raw-webm input required
  adding `trim=0:5,setpts=PTS-STARTPTS` before `split` to produce a clean,
  deterministic 5s body from the ~5.5s recording. Encode codec settings are
  otherwise byte-for-byte the validated baseline.
- **[Rule 2 - Add] Non-black sanity check.** Added an ffmpeg mid-frame probe to
  the encode validation (extract frame at t=2s, fail if < 4 KB) so a black/empty
  capture can never silently ship. Logged per clip.
- The prior `.continue-here.md` DB-egress blocker is resolved (signup works in
  ~4s against the running dev server); `.continue-here.md` removed in this
  commit.
