## Summary

Phase 1 establishes the greenfield project on a stack that has moved since the original research (March 2026). The critical discovery is that **Next.js is now at version 16.2.1** (released October 2025, last updated March 22, 2026) — not 15.x. This has two breaking changes that directly affect Phase 1: the `middleware.ts` file is renamed to `proxy.ts` (the route protection mechanism), and async request APIs (`cookies()`, `headers()`, `params`) are now strictly required with no synchronous fallback. Any code written for Next.js 15 session middleware must use the `proxy.ts` convention from day one.

Better Auth 1.5.6 is fully compatible with Next.js 16 (peer deps declare `^16.0.0`). The Drizzle adapter requires `drizzle-orm >= 0.41.0`; the current published version is 0.45.1, which satisfies this. Better Auth generates its four core tables (`user`, `session`, `account`, `verification`) via `npx auth@latest generate`, producing a Drizzle schema file that must be merged with the app's custom tables. Password reset requires a configured email transport — Resend is the standard choice for Next.js/Vercel stacks. The `@t3-oss/env-nextjs` package (v0.13.11) satisfies the env validation requirement with a `createEnv()` pattern that enforces the server/client boundary at the type level.

Biome is now at v2.4.8 with the `biome ci` command for CI environments. Next.js 16 removes `next lint`, so Biome is the sole linter/formatter in CI — no ESLint needed. The CI pipeline should use `biomejs/setup-biome@v2` GitHub Action plus `tsc --noEmit` and `next build` as three separate steps.

**Primary recommendation:** Start on Next.js 16.2.1. Use `proxy.ts` (not `middleware.ts`) for route protection from the first commit. All request-time APIs (`cookies`, `headers`, `params`) must be awaited. Turbopack is the default build tool — no configuration needed.

### Pattern 1: Better Auth API Route
**What:** Catch-all route handler mounts the Better Auth handler on all `/api/auth/*` requests.
**When to use:** Required — this is how Better Auth receives all auth requests (signin, signup, session, etc.)
**Example:**
```typescript
// Source: https://better-auth.com/docs/integrations/next
// src/app/api/auth/[...all]/route.ts
import { auth } from "@/lib/auth";
import { toNextJsHandler } from "better-auth/next-js";

export const { GET, POST } = toNextJsHandler(auth);
```

### Pattern 2: Better Auth Server Instance with Drizzle Adapter
**What:** The server-side auth instance configured with the Drizzle adapter and email/password.
**When to use:** Single source of truth for auth configuration; import from this file in route handlers and server components.
**Example:**
```typescript
// Source: https://better-auth.com/docs/installation + https://better-auth.com/docs/adapters/drizzle
// src/lib/auth.ts
import { betterAuth } from "better-auth";
import { drizzleAdapter } from "better-auth/adapters/drizzle";
import { nextCookies } from "better-auth/next-js";
import { db } from "@/db";
import * as schema from "@/db/schema";

export const auth = betterAuth({
  database: drizzleAdapter(db, {
    provider: "pg",
    schema, // must pass full schema including Better Auth tables
  }),
  emailAndPassword: {
    enabled: true,
    sendResetPassword: async ({ user, url }) => {
      // call Resend here
    },
  },
  plugins: [nextCookies()], // MUST be last plugin
});
```

### Pattern 3: Next.js 16 Proxy (Route Protection)
**What:** `proxy.ts` (renamed from `middleware.ts` in Next.js 16) — performs lightweight cookie presence check. Does NOT validate the session against the DB; redirects to login when cookie is absent.
**When to use:** Optimistic redirect only. ALWAYS validate the session in RSCs or server actions for any data access.
**Example:**
```typescript
// Source: https://better-auth.com/docs/integrations/next
// src/proxy.ts  (NOT middleware.ts — breaking change in Next.js 16)
import { getSessionCookie } from "better-auth/cookies";
import { NextRequest, NextResponse } from "next/server";

export function proxy(request: NextRequest) {
  const sessionCookie = getSessionCookie(request);
  const { pathname } = request.nextUrl;

  if (!sessionCookie && pathname.startsWith("/dashboard")) {
    const redirectUrl = new URL("/login", request.url);
    redirectUrl.searchParams.set("callbackUrl", pathname);
    return NextResponse.redirect(redirectUrl);
  }

  if (sessionCookie && (pathname === "/login" || pathname === "/signup")) {
    return NextResponse.redirect(new URL("/dashboard", request.url));
  }

  if (pathname === "/") {
    return NextResponse.redirect(new URL("/login", request.url));
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/", "/dashboard/:path*", "/login", "/signup"],
};
```

### Pattern 4: Async Request APIs (Next.js 16 mandatory)
**What:** `cookies()`, `headers()`, `params`, and `searchParams` are now strictly async. The synchronous compat layer from Next.js 15 is removed.
**When to use:** Every time you access cookies or headers in server components or route handlers.
**Example:**
```typescript
// Source: https://nextjs.org/docs/app/guides/upgrading/version-16
// Server component with session
import { auth } from "@/lib/auth";
import { headers } from "next/headers";

export default async function Page() {
  // Must await headers() in Next.js 16
  const session = await auth.api.getSession({
    headers: await headers(),
  });
  if (!session) redirect("/login");
  return <div>Hello, {session.user.name}</div>;
}
```

### Pattern 5: Env Validation (server/client split)
**What:** `@t3-oss/env-nextjs` `createEnv()` with separate server and client schemas, imported as `env` from `src/env.ts`. All modules use `env.VARIABLE_NAME` never `process.env` directly.
**When to use:** All environment variable access — this file is the single import point.
**Example:**
```typescript
// Source: https://env.t3.gg/docs/nextjs
// src/env.ts
import { createEnv } from "@t3-oss/env-nextjs";
import { z } from "zod";

export const env = createEnv({
  server: {
    DATABASE_URL: z.url(),
    BETTER_AUTH_SECRET: z.string().min(32),
    RESEND_API_KEY: z.string().min(1),
  },
  client: {
    NEXT_PUBLIC_APP_URL: z.url(),
  },
  runtimeEnv: {
    DATABASE_URL: process.env.DATABASE_URL,
    BETTER_AUTH_SECRET: process.env.BETTER_AUTH_SECRET,
    RESEND_API_KEY: process.env.RESEND_API_KEY,
    NEXT_PUBLIC_APP_URL: process.env.NEXT_PUBLIC_APP_URL,
  },
});
```

### Pattern 6: Drizzle + Neon DB Singleton
**What:** Single `db` export created from the Neon HTTP driver. The HTTP driver is preferred over WebSocket for serverless (faster for single non-interactive transactions).
**When to use:** Import `db` from `@/db` in all server-side code that needs database access.
**Example:**
```typescript
// Source: https://orm.drizzle.team/docs/connect-neon
// src/db/index.ts
import { neon } from "@neondatabase/serverless";
import { drizzle } from "drizzle-orm/neon-http";
import * as schema from "./schema";

const sql = neon(process.env.DATABASE_URL!);
export const db = drizzle({ client: sql, schema });
```

### Pattern 7: Branded Types in Schema
**What:** Drizzle columns tagged with `.$type<BrandedType>()` to prevent ID mix-ups at the TypeScript level.
**When to use:** All ID columns — `UserId`, `DeckId`, `CardId`, `HabitatId`.
**Example:**
```typescript
// Source: https://orm.drizzle.team/docs/custom-types
declare const __brand: unique symbol;
type Brand<T, B> = T & { [__brand]: B };

export type UserId = Brand<string, "UserId">;
export type DeckId = Brand<string, "DeckId">;

export const users = pgTable("user", {
  id: text("id").primaryKey().$type<UserId>(),
  // ...
});
```

### Anti-Patterns to Avoid
- **Using `middleware.ts` filename in Next.js 16:** Deprecated and warned; rename to `proxy.ts` and export function `proxy`. The `matcher` config still works but warning is emitted on every request.
- **Relying solely on proxy.ts for auth enforcement:** The cookie check is not cryptographically validated. Always call `auth.api.getSession()` before rendering protected data in RSCs.
- **Synchronous `cookies()` or `headers()` calls:** Removed in Next.js 16. The build will type-error if you forget `await`.
- **Importing `process.env` directly:** Always import from `src/env.ts` — this is the pattern enforced by the Zod schema.
- **Barrel imports (`index.ts` re-exports):** Explicitly excluded per project research; import from specific files.
- **Passing full schema object incorrectly to drizzle adapter:** The `drizzleAdapter` requires the `schema` object that includes Better Auth's generated tables. Passing only app tables causes `TypeError: undefined is not an object (evaluating 'e._.fullSchema')`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Session management | Custom JWT logic | Better Auth sessions | Session rotation, CSRF, cookie flags, secure storage — all handled |
| Password hashing | Custom bcrypt/argon2 setup | Better Auth (uses scrypt natively) | scrypt is built into Node.js; correct work factors maintained by library |
| Password reset token generation | Custom UUID + expiry table | Better Auth `sendResetPassword` flow | Token expiry, one-use enforcement, timing-safe comparison — handled |
| Email verification | Custom verification table | Better Auth `emailVerification` config | Token generation + expiry + resend logic all handled |
| Route protection redirects | Complex middleware auth | Better Auth `getSessionCookie()` + proxy.ts | Lightweight cookie presence check is correct pattern for proxy layer |
| Env var validation | Manual `if (!process.env.X) throw` | @t3-oss/env-nextjs | Server/client boundary enforcement; Zod types across the full app |
| DB connection pooling | Manual pg Pool setup | Neon HTTP driver via drizzle-orm/neon-http | Serverless-safe; one HTTP request per query; no stale connections |
| Schema migrations | Manual SQL files | Drizzle Kit (`drizzle-kit generate` + `drizzle-kit migrate`) | Type-safe diff between schema.ts and DB state |

**Key insight:** Better Auth generates its own schema tables. Running `npx auth@latest generate` produces the `auth-schema.ts` file that must be merged into `src/db/schema.ts`. Do not write the `user`, `session`, `account`, or `verification` tables by hand.

## Common Pitfalls

### Pitfall 1: Using `middleware.ts` in Next.js 16
**What goes wrong:** The file runs but emits deprecation warnings on every request. The exported function name `middleware` is also deprecated — it should be `proxy`.
**Why it happens:** Next.js 16 renamed the file convention; documentation and tutorials still use the old name.
**How to avoid:** Create `proxy.ts` at the root of `src/` and export `function proxy(request: NextRequest)`.
**Warning signs:** Console warning "middleware.ts is deprecated" on `next dev` startup.

### Pitfall 2: Synchronous `cookies()` / `headers()` usage
**What goes wrong:** TypeScript type error OR runtime error — synchronous access was removed in Next.js 16 (compat layer from 15 is gone).
**Why it happens:** Next.js 15 had temporary sync compat; 16 removes it. Most tutorials still show sync access.
**How to avoid:** Always `await cookies()`, `await headers()`, `await params`. Use `npx next typegen` to generate typed `PageProps` and `LayoutProps` helpers.
**Warning signs:** TypeScript error `Cannot read properties of undefined reading 'get'` in server components.

### Pitfall 3: `drizzleAdapter` schema mismatch
**What goes wrong:** Runtime error `TypeError: undefined is not an object (evaluating 'e._.fullSchema')` when Better Auth tries to query its tables.
**Why it happens:** The `drizzleAdapter` requires the schema object to include Better Auth's generated tables (`user`, `session`, `account`, `verification`). If you pass only your app tables, it can't find its own tables.
**How to avoid:** Run `npx auth@latest generate` first to get the Better Auth schema. Merge it into `src/db/schema.ts`, then import the full `* as schema` object into `drizzleAdapter(db, { provider: "pg", schema })`.
**Warning signs:** App starts but any auth operation throws a database error.

### Pitfall 4: `nextCookies()` plugin placement
**What goes wrong:** Server actions that call auth functions (e.g., `signIn.email()` from a server action) fail to set cookies, leaving the user in a logged-out state despite successful authentication.
**Why it happens:** Server actions cannot directly set `Set-Cookie` headers. The `nextCookies()` plugin intercepts the auth response to handle this.
**How to avoid:** Add `nextCookies()` to the `plugins` array in `auth.ts`. It MUST be the last plugin in the array.
**Warning signs:** Auth form submits, no error returned, but user stays on the login page.

### Pitfall 5: CVE-2025-29927 Header Bypass
**What goes wrong:** An attacker sends a request with the `x-middleware-subrequest` header, bypassing proxy.ts entirely and accessing protected routes.
**Why it happens:** Next.js versions prior to 15.2.3 / 14.2.25 had a critical vulnerability (CVSS 9.1). All 16.x versions are patched.
**How to avoid:** Use Next.js 16.2.1 (patched). For self-hosted (non-Vercel) deployments, configure the reverse proxy (nginx/Cloudflare) to strip the `x-middleware-subrequest` header. Never rely solely on proxy.ts for security — always validate sessions in server components.
**Warning signs:** Protected routes accessible without a session cookie in local testing.

### Pitfall 6: Turbopack default breaking custom webpack configs
**What goes wrong:** `next build` fails with "Webpack config found but Turbopack is default in Next.js 16."
**Why it happens:** If a dependency installs its own `webpack` configuration (e.g., some older plugins), Turbopack rejects it.
**How to avoid:** For greenfield TioCards, no custom webpack config is needed. If a dependency adds one, use `next build --webpack` to opt out of Turbopack for production builds.
**Warning signs:** Build fails immediately with error about conflicting webpack configuration.

### Pitfall 7: Full-schema DB migration without Phase 1 tables defined
**What goes wrong:** Phase 2+ schema additions fail or require ALTER TABLE migrations if tables weren't defined in Phase 1.
**Why it happens:** The CONTEXT.md specifies all Drizzle tables for all 6 phases must be defined in Phase 1. If implementation stops at auth tables only, later phases create migration debt.
**How to avoid:** Plan 01-03 (DB schema) must include ALL tables: `user`, `session`, `account`, `verification` (Better Auth), plus `decks`, `cards`, `recall_events`, `milestones_seen`, and `habitat_metadata` (app tables). Later phases add columns via migration if absolutely necessary, but never new tables.
**Warning signs:** A Phase 2 plan task says "create decks table" — that should not exist.

### Better Auth Password Reset Flow
```typescript
// Source: https://better-auth.com/docs/authentication/email-password
// In auth.ts — configure the email sender
emailAndPassword: {
  enabled: true,
  sendResetPassword: async ({ user, url }) => {
    // url contains the reset link with token embedded
    // void (don't await) to prevent timing attacks
    void resend.emails.send({
      from: "TioCards <noreply@tiocards.com>",
      to: user.email,
      subject: "Reset your TioCards password",
      text: `Reset your password: ${url}`,
    });
  },
  revokeSessionsOnPasswordReset: true,
},

// Client-side reset page (reads token from URL search params)
const token = new URLSearchParams(window.location.search).get("token");
await authClient.resetPassword({ newPassword, token });
```

| `middleware.ts` + `export function middleware` | `proxy.ts` + `export function proxy` | Next.js 16 (Oct 2025) | All route protection code must use new filename; deprecation warning otherwise |
| Synchronous `cookies()`, `headers()` | Must `await cookies()`, `await headers()` | Next.js 16 (sync compat removed) | Breaking — TypeScript will catch this; codemod available |
| `next lint` command | `biome ci` or `eslint` directly | Next.js 16 (`next lint` removed) | CI pipeline must call biome/eslint directly; `next build` no longer runs linting |
| `middleware` in CI (via `next lint`) | `biome ci .` in GitHub Actions | Next.js 16 | Step change: use `biomejs/setup-biome@v2` action |
| Turbopack opt-in (`--turbopack` flag) | Turbopack default (no flag needed) | Next.js 16 | Remove `--turbopack` from package.json scripts |
| `experimental.turbopack` config | Top-level `turbopack` config in next.config.ts | Next.js 16 | Config key moved out of experimental |
| NextAuth v4 | Better Auth 1.x | NextAuth deprecated 2024 | Better Auth is the current standard for self-hosted App Router auth |

**Deprecated/outdated:**
- `middleware.ts`: Deprecated in Next.js 16; still works with warnings but must be renamed to `proxy.ts`
- `serverRuntimeConfig` / `publicRuntimeConfig`: Removed in Next.js 16 — use env vars directly
- `next lint`: Removed in Next.js 16 — call `biome ci` or `eslint` directly
- `experimental.ppr`: Removed in Next.js 16 — replaced by `cacheComponents` config option

## Open Questions

1. **Email provider credentials for development**
   - What we know: Resend requires an API key and a verified sender domain
   - What's unclear: Whether to use Resend test mode during Phase 1 development or a local SMTP trap (e.g., Mailhog / Mailtrap)
   - Recommendation: Use Resend's test API key for development (emails log but don't send); configure real key in Vercel env vars. Document this in `.env.example`.

2. **Better Auth schema column naming**
   - What we know: Better Auth generates its schema with camelCase TypeScript names mapping to snake_case DB columns
   - What's unclear: Whether Better Auth's generated `user` table `id` field type is compatible with the custom `UserId` branded type without post-generation editing
   - Recommendation: Run `npx auth@latest generate`, inspect the output, apply `.$type<UserId>()` to the `id` column after generation. This is a one-time manual step.

3. **Tailwind CSS 4 configuration in Next.js 16**
   - What we know: Tailwind 4 uses a new CSS-first config (no `tailwind.config.js` by default)
   - What's unclear: Whether the Next.js 16 + Turbopack combination requires any special Tailwind 4 PostCSS configuration
   - Recommendation: Follow the Tailwind 4 installation guide for Next.js specifically; verify PostCSS plugin setup.
