        - Click that row's Pause button (aria-label match)
        - Assert: row gains opacity-50 styling AND a "Paused" badge appears for that row
        - Click "Start studying"
        - Assert: during the study session, the captured front text NEVER appears
          (use page.locator(...).filter({ hasText: capturedFront }).count() === 0

    - Test 2 — "unpausing a card restores it (cadence preserved)":
        - Same setup as Test 1
        - Pause a card; assert "Paused" badge visible
        - Click Resume (aria-label = "Resume this card")
        - Assert: badge disappears (page.getByText("Paused")).toHaveCount(0)
        - Assert: row no longer has opacity-50 (e.g. has class active again, or simply that the Pause aria-label is back)
    - Test 3 — "all cards paused shows the empty-state message":
        - Setup as Test 1; pause ALL three cards in turn
        - Assert: the dashboard shows "All cards are paused — unpause one to study."
        - Unpause one card; assert the message disappears
    - Test 4 — "pause / unpause of a NULL-cooldown card leaves the cooldown NULL":
        - Setup with a fresh card (newly added → cooldownUntil is NULL)
        - Pause then immediately unpause
        - Assert (indirectly — Playwright cannot inspect DB directly without a test seam):
            the card remains in the next assembled study session (start studying →
            captured front text appears) AND no countdown is shown
        - If asserting "no countdown" is brittle, narrow the assertion to "the card
          appears in the very next session" which is sufficient to prove the
          cooldown stayed NULL (a non-null cooldown shifted forward would push it
          out of the immediate session)
    - All tests:
        - Use test.beforeEach for setup so each test starts clean
        - Respect the project's 60s test timeout (no internal sleeps; use Playwright
          web-first assertions via expect(...).toBeVisible() / .toHaveCount(...))
        - No console-noise tolerance: do not introduce console.error that aren't
          already expected by the existing project's test infrastructure
  </behavior>
