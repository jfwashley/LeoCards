<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user filesystem/clipboard -> browser memory | A user File enters client memory via click/drag/paste. NOT a security boundary in Phase 9 — the file is never uploaded or transmitted. Phase 10's endpoint (EXT-05) is the authoritative server-side guard. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-03 | Tampering | ImageDropZone / ImageUploadFlow client validation | accept | `validateImageFile` runs for all three vectors (click/drag/paste), but client-side type+size checks are bypassable by design. This is UX pre-screening, NOT a security control. Authoritative magic-byte + payload validation is explicitly Phase 10 scope (EXT-05). Documented here so it is not mistaken for a security boundary. |
| T-09-04 | Information Disclosure / robustness | Object URL lifecycle | mitigate | Object URLs revoked on replace, clear, and unmount via previewUrlRef + useEffect cleanup (RESEARCH.md Pitfall 1/6). This is a memory-leak robustness concern, not a security boundary — no data leaves the browser. |
| T-09-05 | Tampering | Clipboard paste vector | accept | Pasted files run the same validateImageFile path. Still client-side only and bypassable; same disposition/rationale as T-09-03. |

Note: Phase 9 performs zero network I/O. No server-side threats exist in this phase; the "Extract words" button is an inert no-op. Recorded explicitly so a later reviewer does not mistake client validation for an authoritative control — that control is Phase 10.
