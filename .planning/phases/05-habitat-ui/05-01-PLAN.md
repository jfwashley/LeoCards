2. Create `src/components/habitat-canvas.tsx` — the @pixi/react Application with scene skeleton:
   - Add `"use client"` directive
   - Import `{ Application, extend, useApplication }` from `@pixi/react`
   - Import `{ Container, Sprite, Graphics, Assets, Spritesheet }` from `pixi.js`
   - Call `extend({ Container, Sprite, Graphics })` at MODULE SCOPE (outside any component — required before JSX renders)
   - Export default function `HabitatCanvas({ habitatState }: { habitatState: HabitatState })`
   - Use a `useRef<HTMLDivElement>(null)` for the container ref
   - Render: `<div ref={containerRef} className="w-full" style={{ aspectRatio: "16/9", maxHeight: "70vh" }}>` wrapping `<Application resizeTo={containerRef}>`
   - Inside Application: a `<Scene>` child component that:
     a. Uses `useState<Spritesheet | null>(null)` for tiger sheet, initialized null
     b. Uses `useState<Spritesheet | null>(null)` for habitat sheet, initialized null
     c. In a `useEffect`, calls `Promise.all([Assets.load("/sprites/tiger.json"), Assets.load("/sprites/habitat.json")])` then sets both sheets (per Pitfall 5: load INSIDE Application tree, not before)
     d. If sheets are null, render nothing (loading state handled by habitat-scene.tsx wrapper)
     e. When loaded, render a `<pixiContainer>` with `<VisibilityController />` and placeholder `<pixiSprite>` using `tigerSheet.textures["tiger/happy.png"]`
   - Create `VisibilityController` as a render-nothing component inside the file:
     - Uses `const { app } = useApplication()`
     - `useEffect` adds `visibilitychange` listener: `document.hidden ? app.ticker.stop() : app.ticker.start()` (per D-22)
     - Cleanup removes the listener

   - Do NOT fetch via HTTP — call `getHabitatFacts(session.user.id as UserId)` and `computeHabitatState(facts, new Date())` directly (per RESEARCH.md Open Question 2: avoids HTTP round-trip, consistent with dashboard pattern)
   - Auth check: `const session = await auth.api.getSession({ headers: await headers() }); if (!session) return null;`

   - The `(protected)` route group is already guarded by layout.tsx redirect — the `if (!session) return null` is a safety fallback
