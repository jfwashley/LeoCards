<objective>
Fix the live user-facing bug: extractions above ~30 words deterministically fail translation because `runTranslationFanOut` fires one `fetch("/api/translate")` per word, and >30 words in one minute trips the route's 30/min per-user rate limit → 429 → every remaining word shows "Translation unavailable". Replace the per-word fan-out with ONE batched DeepL request via the SDK's native array overload.

Purpose: This is the ONLY live-in-prod bug in Phase 26, front-loaded as Wave 1 so Josh can push it to prod ahead of the rest of the phase (every push to main auto-deploys prod).
Output: Additive `texts[]` array mode on `/api/translate` (singular `text` contract frozen), first-ever test coverage for that route, and a single-request client fan-out with one retry + fallback.
</objective>
