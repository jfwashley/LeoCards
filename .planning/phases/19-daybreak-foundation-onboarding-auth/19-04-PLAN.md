<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /welcome (RSC) | An unauthenticated or already-onboarded user may hit /welcome directly; the route must guard server-side. |
| client (welcome step 3) -> better-auth /update-user | nativeLanguage crosses from the untrusted client into the user record via authClient.updateUser. |
| client (welcome step 3) -> createDeck server action | targetLang crosses into a DB write. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-04-EOP | Elevation of Privilege | /welcome route + createDeck | mitigate | RSC guard calls auth.api.getSession and redirect("/login") when absent; createDeck independently calls getSession and throws "Unauthorized". A logged-out user cannot persist data via /welcome. |
| T-19-04-MASS | Tampering (mass assignment) | authClient.updateUser | mitigate | better-auth only writes fields declared in auth.ts additionalFields (nativeLanguage is the sole writable additional field); arbitrary extra keys in the updateUser payload are ignored server-side. The client passes only { nativeLanguage }. |
| T-19-04-INJ | Tampering (invalid field value) | nativeLanguage / targetLang | mitigate | Validate native + target with z.enum(["en","fr","es"]) at the call site before updateUser; createDeck re-checks ALLOWED_LANGUAGES server-side and throws on anything else. The user.nativeLanguage column is text, so client+server validation is the guard. |
| T-19-04-AUTHZ | Broken Access Control (re-onboard) | /welcome has-decks guard | mitigate | If the session user already has >=1 deck, the RSC redirects to /dashboard — a returning user cannot re-run welcome or create spurious extra first-decks via back-nav. |
| T-19-04-IDEMP | Data integrity (partial write) | updateUser-then-createDeck ordering | accept | updateUser runs before createDeck; if createDeck fails the user keeps their nativeLanguage and is shown the retry state (deck not created). If updateUser fails, no deck is created. No orphaned half-state that breaks the app (nativeLanguage also has a DB default 'en'). |
| T-19-04-SECRET | Information Disclosure | welcome client components | accept | Client components reference no secrets; only public auth-client + server-action calls. No new secret-leak surface. |
</threat_model>
