<planner_decisions>
- **Only `sunrise` and `daylight` are ported. `dusk` is deliberately left out.** Dusk exists on web
  purely for the reset-password screen, and D-21 keeps password reset entirely on web — there is no
  native screen that could use it. 28.2-UI-SPEC.md §Design Decisions Log signs this off: porting
  unused code contradicts the project's no-gold-plating rule, and it can be added later if a native
  reset flow is ever built.
- **The hills are drawn with `react-native-svg`, not with `borderRadius`.** The web hills are boxes at
  `borderRadius: 50%` with mismatched width and height, i.e. true ellipses. React Native's numeric
  `borderRadius` produces a stadium/pill shape from such a box, not an ellipse — visually wrong in a
  way that is easy to miss. An `Svg` with `preserveAspectRatio="none"` and a unit-circle `Ellipse`
  stretches to exactly the web geometry. `react-native-svg` is already a dependency for Leo.
- **The sun and its glow stay plain `View`s.** They are fixed-size squares, where a numeric
  `borderRadius` of half the side genuinely produces a circle. No SVG needed.
- **Ghost peeks are centred by percentage offsets, not by a translate transform.** The web uses
  `left: 50%` plus `translateX(-50%)`; React Native's `transform` translate takes numbers, so a
  62%-wide peek is placed at `left: "19%"` and a 76%-wide one at `left: "12%"` — arithmetically
  identical, with no reliance on percentage-transform support.
- **The card's shadow and its clipping live on two different views.** On Android, `overflow: "hidden"`
  clips the elevation shadow. An outer view carries the radius and the shadow; an inner view carries
  the same radius plus `overflow: "hidden"` to clip the scene. One view doing both loses the shadow on
  half the target platforms — and RN reports nothing.
</planner_decisions>

Exact values to port:

Scene palettes (`SCENES`) — port `sunrise` and `daylight` only:
- sunrise: gradient `#FFE7BC` → `#FFF3DC` (180deg, i.e. top to bottom), sun `#FFC95C`, glow
  `rgba(255, 201, 92, 0.25)`, hill1 `#F7D592`, hill2 `#EFB964`
- daylight: gradient `#DDEFFF` → `#F1F8FF`, sun `#FFE08A`, glow `rgba(255, 224, 138, 0.30)`,
  hill1 `#CFE0A4`, hill2 `#ADCB79`

`DaybreakAuthScene` — props `variant` (default sunrise), `tagline` (default `Your lion is waiting.`),
`height` (default 216). Contents, in paint order:
1. Gradient background filling the scene box, top-to-bottom.
2. Glow ring: the web draws `boxShadow: 0 0 0 14px {glow}` — a solid 14px spread ring, not a blur.
   React Native has no shadow-spread, so render a second circle BEHIND the sun: diameter 58 + 2×14 =
   86, filled with the glow colour, same centre. With the sun at `right: 30, top: 20` and 58×58, the
   glow sits at `right: 16, top: 6` (28.2-UI-SPEC.md §Native Rendering Notes specifies this exact
   substitution).
3. Sun: 58×58 circle, `right: 30`, `top: 20`, filled with the variant's sun colour.
4. Hill 1: `left: "-18%"`, `bottom: -78`, width `135%`, height 170, ellipse in hill1.
5. Hill 2: `right: "-14%"`, `bottom: -66`, width `125%`, height 140, ellipse in hill2.
6. Four grass tufts at `bottom: 30`, rotated -12°, radius 3, colour `rgba(116, 78, 24, 0.25)`:
   `left 11%` w16, `left 22%` w11, `left 74%` w15, `left 85%` w10 — all height 10.
7. Leo, `LionFace size={88}`, horizontally centred, `bottom: 36`.
8. Tagline, horizontally centred, `bottom: 11`, colour `#8A6235`.

The scene box itself is `overflow: hidden` — the hills and their negative offsets depend on it.

**One deliberate divergence from the web source:** the web tagline renders at 14px/600. Use the
theme's `label` role (13/600) instead — 28.2-UI-SPEC.md §Typography assigns scene taglines to the
Label role explicitly, as part of its approved flattening of near-duplicate sizes. This is the one
place in this component where the approved UI-SPEC overrides the shipped web value; everything else is
a verbatim port.

`AuthCard` — props `scene` (a node) and `children`:
- Outer container: `position: relative`, `paddingTop: 20`, full width.
- Ghost peek 1: `top: 0`, width `62%`, opacity 0.45. Ghost peek 2: `top: 10`, width `76%`, opacity 0.8.
  Both: height 22, white, top corners rounded 22, 1px `#F0E3CF` border with no bottom border.
- Card: radius 22, white, 1px `#F0E3CF` border, card shadow from the theme (iOS `#A06E28` /
  offset 0,12 / opacity 0.16 / radius 30; Android `elevation: 10`), scene at the top, then a content
  area padded 20 top / 22 sides / 22 bottom with a 15 gap between children.

**RN translation reminders.** `gap` is supported on RN views. Percentage `left`/`right`/`width` are
supported in absolute positioning. `boxShadow` strings and CSS gradient strings are NOT — both are
silently ignored, producing no error and no visual, which is why the acceptance criteria assert on the
absence of those string forms.
