Programme decisions D-01..D-20 live in `.planning/phases/28-native-mobile-packaging/28-CONTEXT.md` and remain canonical; this file's new decisions continue that numbering as **D-21..D-36** to keep D-references unambiguous across the 28.x programme.

<domain>
## Phase Boundary

Phase 28.2 turns the bare `mobile/` workspace member (28.1's five-file scaffold) into a real, bootable Expo app delivering NAT-03 and NAT-04:

- **NAT-03 (auth):** The app signs up, signs in, and signs out against the existing better-auth backend with correct session semantics — revocation-sensitive paths use fresh session reads, mirroring the web's `getSession`/`getSessionFresh` split.
- **NAT-04 (offline):** The app is online-required with a friendly Leo-branded offline screen and retry wherever the network is missing — no blank screens, no sync engineering.

Plus the goal's shell obligations: EAS-configured (account + project link + `eas.json`, no builds) and boots to a navigation shell (bottom tabs with Leo-branded placeholders).

**NOT this sub-phase:** core-loop screens — dashboard/study/add-a-word content (28.3), native habitat (28.4), real account section + builds/delivery/identity (28.5), the first-visit welcome flow (explicitly deferred to 28.3 per D-23), notifications, offline sync.

**Server-side footprint is real but tiny:** adding the better-auth Expo plugin + `trustedOrigins` to `src/lib/auth.ts` is a change to the live web backend — pushes auto-deploy prod, so it rides the established Josh-approves-every-push discipline.

</domain>

<decisions>
## Implementation Decisions

### Auth flow scope
- **D-21: Forgot password = native request, web reset.** A native screen takes the email and calls the existing better-auth endpoint; the emailed link opens the web reset page in the phone's browser (`revokeSessionsOnPasswordReset` already covers revocation). No deep-link/reset-token engineering in v1.
- **D-22: Signup mirrors web exactly** — name, email, password, native-language picker (the better-auth `nativeLanguage` additionalField). Identical account shape on both surfaces; no follow-up profile step.
- **D-23: First-visit welcome deferred to 28.3.** A fresh native signup lands on the shell's placeholder home this phase; the 3-step welcome belongs with the core-loop screens it leads into.
- **D-24: Sessions persist indefinitely + friendly note on revocation.** Session token in SecureStore; app boots straight to the shell. A revoked/expired session (password change/reset on web, etc.) lands on the login screen with a gentle "You've been signed out — please sign in again" note — never an unexplained bounce. Mid-session 401s follow the same path.

### Navigation shell
- **D-25: Bottom tabs** — the native convention, not the web's hub-and-spoke.
- **D-26: Full v1 tab set from day one:** Deck, Study, Habitat. Study/Habitat are placeholders until 28.3/28.4 fill them; the shell itself stays stable across the rest of the programme.
- **D-27: Sign-out lives behind a header account glyph** (mirrors web) opening a minimal sheet with just "Sign out" for now. In 28.5 the same entry point becomes the real account section — nothing moves, it grows.
- **D-28: Placeholders are Leo-branded teasers** — Daybreak styling, Leo art, and a friendly line each (e.g. "Your habitat is growing here soon"). The first bootable build should already feel like LeoCards.

### Daybreak & Leo on native
- **D-29: Faithful port of the web's Daybreak auth design** — cream/amber palette, Baloo 2 + Figtree via expo-font, the auth card and lion scene rebuilt natively. The validated web design is the spec; nothing new to invent.
- **D-30: Leo art = react-native-svg redraw** of the web's CSS-drawn Leo — crisp, themeable, animatable later; one translation reused across the auth scene, tab teasers, and the offline screen.
- **D-31: Daybreak tokens = local RN theme module** inside `mobile/` (TS constants for colours/fonts/radii/spacing). No shared tokens package this phase; drift risk accepted while the palette is small and stable.
- **D-32: Offline screen = manual "Try again" + auto-recover.** The screen dismisses itself when the device reports connectivity is back (reachability listener); the button stays for impatient taps. Visual design remains Claude's discretion per the programme's D-15 delegation.

### Done-bar & dev runtime
- **D-33: Done bar = both platforms.** The app demonstrably boots and completes the full auth loop on Josh's physical iPhone (Expo Go over LAN) AND the Android emulator on the dev machine.
- **D-34: Runtime = Expo Go all phase.** No EAS dev build unless 28.3/28.4 hit a hard Expo Go limit (that pull-forward is a later decision; builds otherwise start at 28.5). Every 28.2 dependency must be verified Expo Go-compatible against installed docs.
- **D-35: "EAS-configured" = account + init + eas.json, zero builds.** Create the Expo account (human action: Josh), run `eas init` to link the project ID, commit `eas.json` with build profiles. 28.5 starts from a ready pipeline.
- **D-36: Backend targets = local dev, prod proof.** Day-to-day the app points at the local Next dev server over LAN (test users, zero prod risk). Final NAT-03 acceptance is one real signup/in/out against production with a `*test.local` user, swept by `scripts/cleanup-test-users.mjs` — proving `trustedOrigins` + cookie behaviour on the real deployment.

### Claude's Discretion
- Navigation library (expo-router vs react-navigation — within D-25's bottom-tab structure), state management, styling mechanics — carried from the programme's discretion grants.
- Offline-screen visual design (programme D-15 delegation) and reachability-detection mechanics.
- Exact copy/tone of the signed-out note, teaser lines, and auth-form error messages (Daybreak voice: warm, never blaming).
- SVG component structure for the Leo redraw; EAS config mechanics and build-profile contents.

</decisions>

## Existing Code Insights

### Reusable Assets
- **`mobile/` scaffold (28.1-08):** `package.json` (expo 57.0.10, RN 0.86.2, react 19.2.3, `@leocards/domain`), `app.json` with scheme `"leocards"` already set, working Metro cross-workspace resolution (proven by real bundles). `index.ts` is a placeholder to be replaced by the real app entry.
- **`@leocards/domain`** — `contracts` exports all five native-v1 response shapes + `CoreErrorCode`/`CORE_ERROR_STATUS`; `schemas` exports the zod validation both ends share.
- **12 native-v1 endpoints live in prod** (verified 28.1-09), including `/api/auth/[...all]` (better-auth handler) and `GET /api/account` (the revocation-sensitive read pattern: `disableCookieCache: true`).
- **Web auth pages** — the four `(auth)` pages define field sets, validation, and error copy the native screens mirror.

### Established Patterns
- **Session split (27-01):** cached reads for normal screens, fresh reads for revocation-sensitive paths — NAT-03 requires the native client respect the same semantics (the goal text names it).
- **Screen-shaped REST (D-04):** the app consumes the 28.1 endpoints as-is; no new endpoint work expected this phase beyond the auth.ts plugin/trustedOrigins edit.
- **Pushes are releases:** any `src/lib/auth.ts` change auto-deploys prod on push — sequence server edits into an early, Josh-approved wave with gates green.
- **`*test.local` + cleanup script** — the prod-proof convention (D-36).
- **Installed-docs discipline (AGENTS.md):** researcher verifies better-auth Expo plugin API, SecureStore, netinfo, expo-font, react-native-svg against installed packages, not training data.

### Integration Points
- `src/lib/auth.ts` — add better-auth `expo()` plugin + `trustedOrigins` for the `leocards://` scheme (server-side, prod-deploying).
- `mobile/package.json` / `app.json` — new deps (navigation, expo-font, react-native-svg, expo-secure-store, netinfo, better-auth Expo client) + EAS project ID; supply-chain gate per the 28.1-08 precedent (Josh approves new packages).
- `mobile/index.ts` — replaced by the real app entry + navigation shell.

### Risk intersection worth researching
- **better-auth ≤1.6.21 critical advisory (account-takeover class, non-major fix available)** surfaced by 28.1-09's first-ever `npm audit` — pre-existing, but 28.2 is the auth phase: researcher should check whether the Expo plugin work wants/needs the patched version and surface the upgrade decision to Josh rather than silently bumping (server change = prod deploy + auth-focused regression risk).

- The first bootable build is a **demo artefact** — Josh explicitly chose Leo-branded teasers because "this build is what you'll show people". Charm on first boot matters.
- The signed-out note is **gentle and friendly** ("You've been signed out — please sign in again") — Daybreak voice, never an unexplained bounce, never blame.
