## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest ^4.1.1, root `vitest.config.ts`, `environment: "node"` |
| **Config file** | `vitest.config.ts` (repo root) — its default include glob already collects `mobile/**`, no config change needed |
| **Mobile typecheck** | `npx tsc --noEmit --project mobile/tsconfig.json` — required separately because the root `tsconfig.json` has `"exclude": ["node_modules", "mobile"]`. Verified exiting 0 on the pre-phase tree |
| **Quick run command** | `npx vitest run mobile` |
| **Full suite command** | `npm test` (`vitest run`, repo-wide) |
| **Bundle proof** | `npx expo export --platform android --no-bytecode` from `mobile/`, then grep the emitted JS. The `--no-bytecode` flag is mandatory: SDK 57 emits Hermes bytecode by default, which is not text-searchable (28.1-08 established this) |
| **Estimated runtime** | mobile vitest ~5s · mobile tsc ~15s · full vitest ~60s · `npm run build` ~90s · `expo export` ~25s |

**Two environment constraints every mobile test must respect:**
1. The root `vitest.config.ts` aliases `@` to the WEB app's `./src`. Mobile tests must import their
   subjects with relative paths, or they silently load Next.js code. No mobile source or test file uses
   a `@/` specifier — asserted in plan 28.2-05's acceptance criteria.
2. The node environment cannot render React Native or load `expo-*` native modules. Every unit-tested
   module in this phase is deliberately dependency-free, or mocks its native boundaries (plan 28.2-07's
   auth-client test mocks `expo-secure-store`, `@better-auth/expo/client` and `better-auth/react`).

## Sampling Rate

- **After every task commit:** `npx vitest run mobile` + `npx tsc --noEmit --project mobile/tsconfig.json`
- **After every plan wave:** full `npm test` — 28.2 must never break the web app
- **After any `src/` change (waves 1-2 only):** `npx tsc --noEmit`, `npm run build`, scoped `npx biome check <file>`, `npm run qa:run`
- **After the production deploy (wave 2):** `npm run perf:recert` (AGENTS.md D-14/D-15 cadence)
- **Before `/gsd:verify-work`:** full suite green, plus the manual D-33 device legs and the D-36 production proof
- **Max feedback latency:** ~20s for the per-task loop (mobile vitest + mobile tsc)

**Known flakes — not regressions.** Four files flake under full-suite parallel execution on this project:
`deck-switcher`, `image-upload-flow-extract-errors`, `review-list-commit-guard`, `cooldown-config`. Each
passes in isolation. Re-run any failure alone before reporting it.

### Full-regression gates — exempted from the 30s latency guideline

These six task IDs chain `tsc` + `vitest run` + `npm run build` + `npm ci` (and in one case
`perf:recert`) into a single automated gate, running well past 30 seconds. That is deliberate, not an
oversight: each guards a change that can break the **shipped web app** or **production**, where the cost
of a missed regression dwarfs the cost of the wait. They are distinct from — and do not replace — the
fast per-task loop above (`npx vitest run mobile` + mobile `tsc`, ~20s), which is what runs after every
ordinary commit.

| Task ID | Why it needs the full suite |
|---------|------------------------------|
| 28.2-01-02 | Moves the live backend's auth-core dependency across a minor line; the suite is the only real test of RESEARCH assumption A3 |
| 28.2-03-01 | Edits `src/lib/auth.ts`, on which every existing web auth flow depends |
| 28.2-03-03 | `perf:recert` (~40 min by design) — AGENTS.md's post-deploy D-14/D-15 cadence |
| 28.2-04-02 | Adds ~15 packages to the shared workspace lockfile that Vercel installs on every deploy |
| 28.2-14-01 | Phase gate — the last check before NAT-03/NAT-04 are marked complete |
| 28.2-14-02 | Touches production directly (real signup, then a sweep of the production database) |

Only 6 of 39 tasks are exempted; the remaining 33 sit inside the fast loop.

## Wave 0 Requirements

No separate Wave 0 plan is needed — **no framework install is required** (the root vitest config already
collects `mobile/**` with zero configuration), and every test file is created by the same task that
creates its subject, in a RED→GREEN commit pair. The seven files below are the phase's new automated
coverage:

- [ ] `mobile/components/daybreak/__tests__/field-state.test.ts` — field error/hint precedence (plan 06)
- [ ] `mobile/lib/__tests__/auth-schemas.test.ts` — NAT-03 field rules and error copy (plan 07)
- [ ] `mobile/lib/__tests__/auth-client.test.ts` — NAT-03 fresh-vs-cached session split (plan 07)
- [ ] `mobile/lib/__tests__/session-notice.test.ts` — D-24 consume-once notice (plan 07)
- [ ] `mobile/lib/__tests__/auth-errors.test.ts` — non-enumerating failure mapping (plan 09)
- [ ] `mobile/lib/__tests__/session-gate.test.ts` — revocation vs deliberate sign-out (plan 12)
- [ ] `mobile/components/__tests__/offline-state.test.ts` — NAT-04 transitions incl. unknown reachability (plan 13)

RESEARCH's Validation Architecture named three of these as gaps; the other four emerged from extracting
behavioural rules out of components that the node environment cannot render, so that each rule is
covered by a real assertion rather than by a source grep.

**Explicitly not installed:** `jest-expo` / `@testing-library/react-native`. RESEARCH recommends against
standing them up for this phase, since D-33's manual device done-bar exercises rendering more faithfully
than a simulated renderer would.
