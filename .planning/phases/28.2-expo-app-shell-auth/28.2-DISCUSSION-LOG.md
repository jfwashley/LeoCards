## Auth flow scope

**Q1: How should "Forgot password?" work in the native app for v1?**

| Option | Description | Selected |
|--------|-------------|----------|
| Native request, web reset (Recommended) | Native screen takes the email, calls the existing better-auth endpoint; emailed link opens the web reset page in the phone's browser | ✓ |
| Fully native reset | Deep-link the emailed URL into the app (leocards:// scheme) + native new-password screen | |
| Omit from v1 | No forgot-password entry point in the app | |

**User's choice:** Native request, web reset

**Q2: What should native signup collect?**

| Option | Description | Selected |
|--------|-------------|----------|
| Mirror web exactly (Recommended) | Name, email, password, native-language picker — identical account shape on both surfaces | ✓ |
| Minimal: email + password | nativeLanguage silently defaults to English; name empty until edited on web | |
| You decide | Claude picks at plan time | |

**User's choice:** Mirror web exactly

**Q3: Where does the first-visit welcome flow (web's 3-step intro) belong on native?**

| Option | Description | Selected |
|--------|-------------|----------|
| Defer to 28.3 (Recommended) | Fresh signup lands on the shell's placeholder home; the welcome flow leads into core-loop territory 28.3 owns | ✓ |
| Build it in 28.2 | Shell owns the first-boot experience; three more Daybreak screens this phase | |
| Skip on native v1 | Native users never see the intro | |

**User's choice:** Defer to 28.3

**Q4: How should the app behave around session persistence and revocation?**

| Option | Description | Selected |
|--------|-------------|----------|
| Persist + friendly note (Recommended) | Stay signed in indefinitely (SecureStore); revoked/expired session lands on login with a gentle "You've been signed out" note | ✓ |
| Persist, silent bounce | Same persistence; dead session shows login with no explanation | |
| Time-boxed sessions | Force re-login after a fixed period | |

**User's choice:** Persist + friendly note
