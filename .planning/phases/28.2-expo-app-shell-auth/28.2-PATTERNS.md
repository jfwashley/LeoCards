## Pattern Assignments

### Group A — `mobile/app/_layout.tsx` (root auth gate)

**Analog 1 — the concept:** `src/app/(protected)/layout.tsx` (full file, 16 lines) — this IS the web's auth gate; `Stack.Protected` is its RN equivalent:
```typescript
import { redirect } from "next/navigation";
import { getSession } from "@/lib/auth-session";

export default async function ProtectedLayout({ children }: { children: React.ReactNode }) {
  const session = await getSession();
  if (!session) redirect("/login");
  return <>{children}</>;
}
```

**Analog 2 — the RN mechanics (no in-repo precedent, from RESEARCH.md Pattern 3 + Pattern 5, official docs + verified source):**
```tsx
import { Stack } from "expo-router";
import { authClient } from "@/lib/auth-client";

function RootNavigator() {
  const { data: session, isPending } = authClient.useSession();
  if (isPending) return null; // splash screen stays visible

  return (
    <Stack>
      <Stack.Protected guard={!!session}>
        <Stack.Screen name="(tabs)" options={{ headerShown: false }} />
      </Stack.Protected>
      <Stack.Protected guard={!session}>
        <Stack.Screen name="(auth)" options={{ headerShown: false }} />
      </Stack.Protected>
    </Stack>
  );
}
```
Font loading + splash hold (D-34, Expo Go has no config plugins) wraps this — `useFonts()` + `SplashScreen.preventAutoHideAsync()`/`hideAsync()`, see RESEARCH.md Pattern 5 verbatim.

**D-24 signed-out note:** when a session is revoked (mid-session 401, or boot finds a stale token), the gate lands on `(auth)/login` — the note itself ("You've been signed out — please sign in again") is passed as e.g. a router param or a small module-level flag the login screen reads once, since there's no existing web precedent for this (web never silently loses a session mid-browse the same way). Treat as new UI, Daybreak-toned per CONTEXT.md's copy guidance.

### Group B — Auth screens (signup / login / forgot-password)

**These are faithful ports (D-29) — the web files ARE the spec.** Below is the shared shape all three follow; per-screen deltas noted after.

**Imports pattern**, `src/app/(auth)/signup/page.tsx` lines 1-13:
```typescript
"use client";
import { zodResolver } from "@hookform/resolvers/zod";
import Link from "next/link";
import { useRouter } from "next/navigation";
import { useState } from "react";
import { useForm } from "react-hook-form";
import * as z from "zod/mini";

import { AuthCard, DaybreakAuthScene } from "@/components/daybreak/auth-card";
import { TBtn } from "@/components/daybreak/t-btn";
import { TField } from "@/components/daybreak/t-field";

```
Native swaps: `"use client"` drops (no RSC boundary), `next/link`→`expo-router`'s `Link`, `next/navigation`'s `useRouter`→`expo-router`'s `useRouter`, `zod/mini`→full `zod` (RESEARCH.md Open Question 1 recommendation — no CWV constraint on native), import paths become relative or a `mobile/`-local `@/` alias per `mobile/tsconfig.json`.

**Schema pattern**, `signup/page.tsx` lines 15-19 (mirror in full `zod`, and ADD the `nativeLanguage` field per D-22 — the web signup form doesn't collect it today, confirmed by `src/app/(auth)/__tests__/signup-payload.test.tsx` lines 63-72 asserting `nativeLanguage` is absent from the web payload; native's payload SHOULD include it):
```typescript
const signupSchema = z.object({
  name: z.string().check(z.minLength(1, "Name is required")),
  email: z.email("Please enter a valid email"),
  password: z.string().check(z.minLength(8, "Password must be at least 8 characters")),
});
```

**Core submit pattern**, `signup/page.tsx` lines 36-56 — the exact `authClient` call shape to mirror (method names carry over 1:1 to the native `authClient` since it's the same better-auth client API):
```typescript
async function onSubmit(values: SignupFormValues) {
  setIsPending(true);
  setEmailError(null);
  try {
    const { error } = await authClient.signUp.email({
      email: values.email,
      password: values.password,
      name: values.name,
    });
    if (error) {
      setEmailError("An account with this email already exists.");
      return;
    }
    router.push("/welcome"); // NATIVE: router.replace to a (tabs) route — welcome is deferred to 28.3 (D-23), land on the tab shell instead
  } finally {
    setIsPending(false);
  }
}
```

**Login's open-redirect guard** (`login/page.tsx` lines 51-58) — a real, already-fixed security pattern (CR-01) worth knowing even though native has no query-string `callbackUrl` to sanitise the same way:
```typescript
const callbackUrl = searchParams.get("callbackUrl");
const safeCallback =
  callbackUrl?.startsWith("/") && !callbackUrl.startsWith("//")
    ? callbackUrl
    : "/dashboard";
router.push(safeCallback);
```
The analogous native concern is D-21's password-reset `redirectTo` (see forgot-password below) — same "never accept an arbitrary redirect target" discipline, different call site.

**Forgot-password's D-21-specific delta** — `forgot-password/page.tsx` lines 36-48:
```typescript
await authClient.requestPasswordReset({
  email: values.email,
  redirectTo: `${window.location.origin}/reset-password`,
});
setSentEmail(values.email);
setSent(true);
```
Native has no `window.location.origin` — hardcode/constant the web app's own origin (e.g. from `mobile/lib/config.ts`, NOT client-suppliable) so `redirectTo` always points at the real web reset page. This is exactly the open-redirect threat pattern RESEARCH.md's Security Domain flags ("Hardcode/constant the web reset-page URL server-side or validate it against an allow-list"). The sent-confirmation UI (lines 50-89, envelope icon + "If an account exists, we've sent a reset link to `{email}`" + resend link) ports near-verbatim. **`reset-password/page.tsx` itself has NO native equivalent** — D-21 keeps the entire reset completion on web; the emailed link opens in the phone's system browser via `Linking.openURL()`, never re-entering the app.

**Error-copy convention** (all three screens): generic, non-enumerating messages — `"An account with this email already exists."`, `"Incorrect email or password."` — never confirm/deny which field was wrong beyond that. Preserve this exactly (Daybreak voice: warm, never blaming, per CONTEXT.md).

### Group C — Daybreak component ports

**`auth-card.tsx`** — `src/components/daybreak/auth-card.tsx` full file (209 lines) is the spec. Both components are otherwise pure inline-style objects with no Tailwind classes to untangle — good porting candidates per RESEARCH.

**`lion-face.tsx`** — `src/components/daybreak/lion-face.tsx` full file (115 lines) is the geometry/colour spec (mane `#E8973B`, face `#FFD9A6`, muzzle `#FFF1DC`, ink `#4A331C`), built from absolutely-positioned `<div>` circles/ellipses on a percentage grid (`u(n) = (n/100) * size`). D-30 requires a `react-native-svg` redraw, not a `View`-based port — translate each `disc()`/positioned-div into an `<Circle>`/`<Ellipse>` on the same percentage grid so the proportions match exactly. Keep the `LionFaceProps` shape (`size`, `mane`, `face`, `muzzle`, `ink`, `outline`) — it's already parameterised for reuse (D-30's stated goal: "one translation reused across the auth scene, tab teasers, and the offline screen").

**`t-field.tsx`** — `src/components/daybreak/t-field.tsx` full file (42 lines). Shape to keep: `label`/`error`/`hint` props, error message replaces hint when present, border colour swaps to `--destructive` on error:
```typescript
interface TFieldProps extends React.InputHTMLAttributes<HTMLInputElement> {
  label: string;
  error?: string;
  hint?: string;
}
```
**Concrete gotcha (not flagged in RESEARCH.md, found by reading the actual code):** this component's whole implementation is `React.forwardRef` + `{...inputProps}` spread onto a native `<input>`, and the auth screens drive it via react-hook-form's `{...register("email")}` shorthand (`signup/page.tsx` line 87). React Native's `TextInput` fires `onChangeText(text: string)`, not a DOM `onChange(event)` — `register()`'s returned `{ onChange, onBlur, name, ref }` object assumes a DOM-shaped event target and will not wire up correctly if spread onto `TextInput`. The native `TField` must use react-hook-form's `<Controller>` instead, mapping `field.onChange` to `TextInput`'s `onChangeText`:
```tsx
<Controller
  control={control}
  name="email"
  render={({ field }) => (
    <TextInput value={field.value} onChangeText={field.onChange} onBlur={field.onBlur} />
  )}
/>
```
This affects every field in every Group B screen — flag it once here, apply everywhere `register()` appears in the web source.

**`t-btn.tsx`** — `src/components/daybreak/t-btn.tsx` full file (33 lines). Prop shape (`isPending`, `disabled`, `children`) ports as-is; swap `<button disabled={...}>` for `<Pressable disabled={...}>` (or `TouchableOpacity`), and `<Loader2 className="animate-spin" />` for RN's `<ActivityIndicator />`:
```typescript
export function TBtn({ isPending, children, disabled, className, ...props }: TBtnProps) {
  return (
    <button disabled={isPending || disabled} className={[...]} {...props}>
      {isPending ? <Loader2 className="size-5 animate-spin" /> : children}
    </button>
  );
}
```
Keep: 50px height, full-width, bold 16px label, amber shadow (`--db-btn-shadow: 0 10px 22px rgba(242, 138, 31, 0.3)` → RN shadow props), 0.6 opacity when disabled.

**`pill.tsx`** — `src/components/daybreak/pill.tsx` full file (23 lines), trivial port: `<span>`→`<View>` wrapping `<Text>`, pill-bg/pill-text tokens (`--db-pill-bg: #fff1dc`, `--db-pill-text: #b4762a`) carry over unchanged.

### Group F — Offline screen (D-32)

**No web analog** — the web app has no offline-detection concept at all (a browser tab just fails its fetches). This is genuinely new territory; RESEARCH.md Pattern 4 (sourced from the current `react-native-netinfo` README) is the authoritative starting point:
```tsx
import NetInfo from "@react-native-community/netinfo";
import { useEffect, useState } from "react";

export function useIsOnline() {
  const [isOnline, setIsOnline] = useState(true);
  useEffect(() => {
    return NetInfo.addEventListener((state) => {
      setIsOnline(state.isInternetReachable ?? state.isConnected ?? false);
    });
  }, []);
  return isOnline;
}
```
Per RESEARCH.md's own Open Question 5 and the Validation Architecture's Wave-0 test file (`mobile/components/__tests__/offline-state.test.ts`), extract the actual online→offline→auto-recover **transition logic** out of this hook into a pure, dependency-free function (e.g. `deriveOfflineScreenState(prev, event)`) so it can be unit-tested under the existing `environment: "node"` vitest config without touching the real NetInfo native module — the hook becomes a thin wrapper calling that pure function on each event. Visually, D-32 + D-30 point back at Group C/D's `DaybreakAuthScene`/`LionFace` composition (Leo-branded, manual "Try again" button using the `TBtn` port, auto-dismiss on reachability restore).

### Group G — `lib/` files

**`auth-client.ts`** — structural analog `src/lib/auth-client.ts` (full file, 9 lines):
```typescript
import { inferAdditionalFields } from "better-auth/client/plugins";
import { createAuthClient } from "better-auth/react";
import type { auth } from "@/lib/auth";

export const authClient = createAuthClient({
  baseURL: process.env.NEXT_PUBLIC_APP_URL,
  plugins: [inferAdditionalFields<typeof auth>()],
});
```
The native version needs the SecureStore-backed `expoClient()` plugin, which has no in-repo precedent — use RESEARCH.md Pattern 2 verbatim (verified against downloaded `@better-auth/expo` source, not just docs):
```typescript
import { createAuthClient } from "better-auth/react";
import { expoClient } from "@better-auth/expo/client";
import * as SecureStore from "expo-secure-store";

export const authClient = createAuthClient({
  baseURL: process.env.EXPO_PUBLIC_API_BASE_URL,
  plugins: [
    expoClient({ scheme: "leocards", storagePrefix: "leocards", storage: SecureStore }),
  ],
});

export const getSessionFresh = () =>
  authClient.getSession({ query: { disableCookieCache: true } });
```
The `getSessionFresh` split mirrors `src/lib/auth-session.ts` (full file, 36 lines) — the web's `getSession`/`getSessionFresh` pair, RSC-`cache()`-wrapped there but the underlying `disableCookieCache: true` query flag is the part that actually matters and translates directly:
```typescript
export const getSessionFresh = cache(async () => {
  return auth.api.getSession({ headers: await headers(), query: { disableCookieCache: true } });
});
```
