<interfaces>
**Test-user convention.** `scripts/cleanup-test-users.mjs` (37 lines) defaults to the pattern
`%@leocards-test.local` and hard-refuses any pattern not ending in a `test.local` domain, exiting 1
with a FATAL message. `npm run qa:cleanup` invokes it with `%@test.local`. Use an address in that
domain for the production run so the sweep can find it.

**Reading DATABASE_URL safely.** `.env.local` on this repo contains a runnable curl-plus-API-key block
that EXECUTES if the file is sourced — 27-02 hit this. Extract the variable with `grep`, never with
`source`.

**Expo Go over LAN.** `npx expo start` from `mobile/` serves the bundle to devices on the same Wi-Fi.
`localhost` will not work from a physical phone; `mobile/.env.local`'s
`EXPO_PUBLIC_API_BASE_URL` must be the machine's LAN IP with the dev server's port for the local legs.
Metro inlines `EXPO_PUBLIC_*` at bundle time, so after changing that value the dev server must be
restarted (and the app reloaded) for the new value to take effect — a silent-stale-value trap worth
checking first if requests go to the wrong host.

**What the loop must cover on each platform (D-33):**
1. Cold launch with no session lands on the login screen inside the Daybreak shell
2. Sign up creates an account and lands on the tab shell (no welcome flow — D-23 defers it to 28.3)
3. All three tabs render their Leo teasers, and the active tab is amber
4. The header account glyph opens the sheet; Sign out returns to login with NO notice
5. Sign in with the same credentials returns to the tab shell
6. Killing and relaunching the app lands straight on the tab shell — the session persisted (D-24)
7. Forgot-password sends and shows the `Check your email` state
8. Turning on airplane mode shows the offline screen; turning it off dismisses it without a tap (D-32)

**Web regression to re-confirm at the gate:** `npx tsc --noEmit`, `npx tsc --noEmit --project
mobile/tsconfig.json`, `npx vitest run`, `npm run build`, `npm ci`, and `npm run qa:run` if
`DATABASE_URL` and `DEBUG_CHEAT_SECRET` are available. Four full-suite vitest flakes are documented on
this project (`deck-switcher`, `image-upload-flow-extract-errors`, `review-list-commit-guard`,
`cooldown-config`) — re-run any failure in isolation before calling it a regression.

**Known open item to carry if it did not resolve:** plan 28.2-04's probe recorded whether Android
tooling actually exists on this machine (RESEARCH Assumption A5). If it did not, the Android leg needs
Android Studio installed first, and that prerequisite must be surfaced here rather than quietly
dropping half of D-33's done bar.
</interfaces>
