<planner_decisions>
- **`TField` stays presentational; react-hook-form lives in the screens.** This mirrors the web split
  exactly (the web `TField` is a dumb forwardRef over `<input>`; the pages own `useForm`). The native
  screens will wrap it in `<Controller>` and map `field.onChange` to `onChangeText` — the concrete
  gotcha 28.2-PATTERNS.md Group C found by reading the real code: `register()`'s returned object
  assumes a DOM-shaped event target and will not wire up against `TextInput`.
- **The field's error/hint precedence is extracted into a pure module.** The repo's vitest runs in a
  node environment with no React Native renderer, and RESEARCH explicitly recommends against standing
  up `jest-expo` this phase. Extracting the one real behavioural rule ("error replaces hint; border
  goes destructive") into `field-state.ts` gives this plan genuine automated coverage rather than a
  source-grep standing in for a test.
- **Leo is drawn in a `viewBox="0 0 100 100"` coordinate space.** The web component already works on a
  0-100 percentage grid via its `u(n) = (n/100) * size` helper, so a 100-unit viewBox makes every
  ported number identical to the source — no arithmetic, no drift, and `size` becomes a pure
  width/height prop.
- **`testID` is forwarded explicitly by both atoms.** 28.2-UI-SPEC.md's testID contract names
  `login-email-field`, `login-submit-btn` and friends, and this project has already been bitten by
  shared atoms that swallow test identifiers (25-03 had to wrap `Card`/`ACBanner` in plain divs).
  Forward it from the start.
</planner_decisions>

<interfaces>
**Leo geometry — the exact translation from the web's absolutely-positioned divs to SVG primitives.**
Source: `src/components/daybreak/lion-face.tsx` (115 lines, read in full this planning session). Every
web value is a percentage of `size`, so in a `viewBox="0 0 100 100"` they carry over unchanged:

| Web element | Web box | SVG primitive |
|---|---|---|
| mane disc | `inset: 0`, background `mane` | `Circle cx=50 cy=50 r=50` fill `mane` |
| left ear | `left:13 top:6 w:20 h:20`, background `face` | `Circle cx=23 cy=16 r=10` fill `face` |
| right ear | `right:13 top:6 w:20 h:20` | `Circle cx=77 cy=16 r=10` fill `face` |
| face disc | `left:17 top:17 w:66 h:66` | `Circle cx=50 cy=50 r=33` fill `face` |
| left eye | `left:35 top:42 w:6 h:6`, background `ink` | `Circle cx=38 cy=45 r=3` fill `ink` |
| right eye | `right:35 top:42 w:6 h:6` | `Circle cx=62 cy=45 r=3` fill `ink` |
| muzzle | `left:37 top:56 w:26 h:18`, background `muzzle` | `Ellipse cx=50 cy=65 rx=13 ry=9` fill `muzzle` |
| nose | `left:46.5 top:56 w:7 h:6`, background `ink` | `Ellipse cx=50 cy=59 rx=3.5 ry=3` fill `ink` |

Draw order must match the web's DOM order (mane, ears, face, eyes, muzzle, nose) — later elements
paint on top.

Prop shape to keep identical to the web component (D-30 calls for one reusable translation):
`size` (default 80), `mane` (default `#E8973B`), `face` (default `#FFD9A6`), `muzzle` (default
`#FFF1DC`), `ink` (default `#4A331C`), `outline` (optional). When `outline` is set, the web applies a
border of `max(1.5, size * 0.028)` px to the mane, ear and face discs only — in viewBox units that is
`stroke` with `strokeWidth = (max(1.5, size * 0.028) / size) * 100` on those three shapes, and no
stroke on eyes, muzzle or nose. When `outline` is unset, no stroke at all.

The web component sets `aria-hidden="true"` — Leo is decorative. 28.2-UI-SPEC.md §Accessibility
Contract carries that over: keep it out of the accessibility tree on native too.

**`TField` — source `src/components/daybreak/t-field.tsx` (42 lines, read in full).** Structure:
column, gap 6 (`gap-1.5`); label at 13/600 in ink; input 48 high (`h-12`), radius 12 (`rounded-xl`),
border width 1.5, background `#FFFBF4`, horizontal padding 14 (`px-3.5`), text 15; error message at
13/600 in `#DE5F4A` replacing the hint; hint at 12.5 in muted when there is no error. Border is
`#EDDFC9` normally and `#DE5F4A` on error.

Two RN translations beyond styling: the label is a `Text`, not a `<label htmlFor>` (use
`accessibilityLabel` on the `TextInput` to preserve the association), and the hint's 12.5px size
becomes the theme's `label` size 13 — 28.2-UI-SPEC.md §Typography flattened those sub-2px variants
into the declared roles deliberately.

**`TBtn` — source `src/components/daybreak/t-btn.tsx` (33 lines, read in full).** Props `isPending`,
`disabled`, `children`. Disabled when either is true. Height 50, full width, radius 14, amber
`#F28A1F` background, label in Figtree 700 at 16 (NOT Baloo 2 — 28.2-UI-SPEC.md §Typography documents
this correction against the design README, with the shipped code as the authority), amber shadow from
the theme's button shadow tokens, opacity 0.6 when disabled. When `isPending`, the web swaps the label
for a spinning `Loader2`; native uses RN's built-in `ActivityIndicator` (28.2-UI-SPEC.md §Design
Decisions Log — no icon library is added this phase).
