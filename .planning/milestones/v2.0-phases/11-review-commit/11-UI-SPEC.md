# Phase 11 — UI Design Contract

> Visual and interaction contract for Phase 11: Review & Commit.
> Generated by gsd-ui-researcher. Consumed by gsd-ui-checker, gsd-planner, gsd-executor, gsd-ui-auditor.
>
> **Scope:** This phase's entire UI surface is rendered by `image-upload-flow.tsx` on the `EXTRACT_SUCCESS` hand-off (when `state.extractWords` is a non-empty array). All tokens, primitives, spacing, typography, and color are **inherited from Phase 9 / Phase 10 (09-UI-SPEC.md, 10-UI-SPEC.md)** — this document specifies DELTAS only.
>
> The PRIMARY deliverable of this spec is the **copy contract** (all labels, headings, per-state messages, summary template) and the **row layout + list ordering** for the two-step review flow.

**Accent reserved for (Phase 11 additions):**
1. (Inherited) Focus ring on all interactive elements
2. (Inherited) "Extract words" CTA button — idle state (Phase 9/10)
3. (Inherited) Extraction spinner — in-flight state (Phase 10)
4. **(New)** "Add N cards" commit button (`variant="default"`) — the primary CTA for Step B
5. **(New)** Loader2 spinner inside "Adding cards…" commit button during in-flight commit state

**Note on "Next" button accent:** "Next: translate" in Step A is the primary forward action for that step — it uses `variant="default"` (accent fill). This is consistent with the Phase 9 precedent for step-advance CTAs. It is NOT an overuse of accent because it only appears while the commit button is not yet visible.

## Interaction States

### Entry Point: EXTRACT_SUCCESS hand-off

When `state.extractWords` is a non-empty string array, `image-upload-flow.tsx` renders `<ReviewList>` in place of the Phase 10 "Review words →" stub. The recap thumbnail, deck selection, and DeckSwitcher are **not shown** in the review phase — the deck is already confirmed. The user is now in the review context.

```
// image-upload-flow.tsx — replace the Phase 10 stub:
if (Array.isArray(state.extractWords) && state.extractWords.length > 0) {
  return (
    <ReviewList
      words={state.extractWords}
      deckId={state.selectedDeckId}
      nativeLang={nativeLang}
      targetLang={deck.language}
      onCancel={() => dispatch({ type: "BACK_TO_PICK" })}
    />
  );
}
```

`onCancel` dispatches `BACK_TO_PICK` in the outer reducer — returns to Step 1 empty state, zero DB writes (D-14).

### Step A → Step B: Translating in-flight

**Trigger:** User clicks "Next: translate" with at least one word kept.

**What happens:** DeepL `/api/translate` called for each kept word (target→native direction). This is a client-side async fan-out, not a single request.

**Layout during translation fan-out:**

```
flex flex-col gap-4
  <p className="text-sm font-medium text-foreground">Translating words…</p>
  [Loader2 spinner — standalone, NOT inside a button]
    <div className="flex items-center gap-2 text-sm text-muted-foreground">
      <Loader2 className="size-4 animate-spin text-primary" aria-hidden="true" />
      Translating {N} word{plural}…
    </div>
  [Step A word list — hidden / not rendered during translation]
  [Cancel button — still visible]
    <Button variant="ghost" onClick={onCancel}> Cancel </Button>
```

**Rationale:** Translation is per-word fan-out (not a single spinner-in-button). A standalone spinner with copy communicates batch progress without requiring a button. Cancel remains available — cancels the whole review with zero writes.

### Step B — Translate & Edit

**Trigger:** All per-word translation attempts complete (both successes and per-word failures — translation never blocks, D-07).

**Layout:**

```
flex flex-col gap-4
  [Step B heading row]
    <p className="text-sm font-medium text-foreground">Check translations</p>
    <p className="text-sm text-muted-foreground">Edit any translation before adding to your deck.</p>
  [translation list — flex flex-col gap-4]
    [ReviewTranslationRow × kept-words-count]
  [action row]
    <Button variant="ghost" onClick={() => setStep("A")}> ← Back </Button>
    <Button variant="ghost" onClick={onCancel}> Cancel </Button>
    <Button variant="default" className="w-full h-11"
      disabled={isCommitting}
      onClick={handleCommit}>
      Add {N} card{plural}
    </Button>
```

**ReviewTranslationRow layout (Step B) — mirrors TranslationForm exactly per RVW-03/D-09:**

```
flex flex-col gap-2
  <div className="grid grid-cols-1 md:grid-cols-2 gap-2">
    <div className="flex flex-col gap-1">
      <Label htmlFor={`native-${i}`}>{nativeLangLabel}</Label>
      {isLoadingTranslation ? (
        <div className="bg-muted animate-pulse rounded-md h-8 w-full" />
      ) : (
        <Input
          id={`native-${i}`}
          value={row.nativeText}
          onChange={...}
          placeholder={`Type in ${nativeLangLabel}…`}
          className="h-8"
          aria-label={`Native translation for "${row.targetText}"`}
        />
      )}
    </div>
    <div className="flex flex-col gap-1">
      <Label htmlFor={`target-${i}`}>{targetLangLabel}</Label>
      <Input
        id={`target-${i}`}
        value={row.targetText}
        onChange={...}
        placeholder={`Type in ${targetLangLabel}…`}
        className="h-8"
        aria-label={`Target word for card ${i + 1}`}
      />
    </div>
  </div>
  {row.translationError && (
    <p className="text-sm text-destructive mt-1" role="alert">
      {row.translationError}
    </p>
  )}
```

**Translation shimmer:** while a per-row translation is in-flight, the native `<Input>` is replaced by `<div className="bg-muted animate-pulse rounded-md h-8 w-full" />` — exact same pattern as `TranslationForm`'s `isNativeReceiving` skeleton (Phase 02 decision: "Skeleton shimmer replaces Input component during in-flight translation").

**Per-row translation failure:** the row shows an inline error below both fields and the native Input is left empty (user must type manually). The row is NOT removed. Other rows' translations proceed. Error copy: `"Translation unavailable — enter manually."` — matches `TranslationForm`'s exact string.

### Commit in-flight

**Trigger:** User clicks "Add N cards" in Step B.

```
[Step B heading — unchanged]
[translation list — still visible, all inputs disabled]
  (each Input gets disabled={true} during commit)
[action row]
  {/* Back and Cancel hidden during commit — no navigation allowed mid-write */}
  <Button variant="default" className="w-full h-11" disabled aria-busy="true"
    aria-label="Adding cards, please wait">
    <Loader2 className="size-4 animate-spin mr-2" aria-hidden="true" />
    Adding cards…
  </Button>
  <p className="text-sm text-muted-foreground text-center">
    Adding {N} card{plural} to your deck…
  </p>
```

**Back and Cancel hidden during commit** — prevents navigation mid-write (mirrors Phase 10's Back hidden during extraction). Inputs disabled during commit to communicate locked state.

### Success Summary

**Trigger:** All `saveCard` calls complete (regardless of individual failures — continue-on-failure per D-12).

```
flex flex-col items-center gap-4 py-6 text-center
  <CheckCircle2 className="size-8 text-green-600" aria-hidden="true" />  {/* optional — see Component Inventory */}
  <div>
    <p className="text-sm font-medium text-foreground">
      {addedCount} card{addedCount !== 1 ? 's' : ''} added to your deck.
    </p>
    {(skippedCount > 0 || failedCount > 0) && (
      <p className="text-sm text-muted-foreground mt-1">
        {[
          skippedCount > 0 ? `${skippedCount} already learned (skipped)` : null,
          failedCount > 0 ? `${failedCount} failed` : null,
        ].filter(Boolean).join(' · ')}
      </p>
    )}
  </div>
  <Button variant="default" className="w-full h-11" onClick={handleGoToDeck}>
    Go to my deck
  </Button>
```

**`handleGoToDeck`:** navigates to `/dashboard?deck={deckId}` — same URL pattern as existing deck navigation (Phase 02 decision: "URL params (?deck=id) for active deck state").

**Zero-cards-added edge case (all failed):** If `addedCount === 0` and `failedCount > 0`, the primary message becomes `"Couldn't add cards — please try again."` and the CTA becomes `"Back to deck"` with `variant="outline"` (no accent for a failure-only outcome).

---

### Cancel (any step)

**Trigger:** "Cancel" button at any point before commit completes.

**Behaviour:** dispatches `BACK_TO_PICK` on the outer `imageFlowReducer` (zero DB writes, D-14). No confirm dialog. The review state machine is destroyed. The outer flow returns to Step 1 empty state.

**No confirmation dialog is required** — nothing has been persisted until Confirm is clicked and `saveCard` calls complete (D-14).

### Destructive Actions

| Action | Approach |
|--------|----------|
| Cancel review (any step before commit) | No confirmation dialog. Immediate zero-write discard. "Cancel" button label is sufficient; the casualness of the action (D-14: nothing is persisted until Confirm) makes a dialog unnecessary and disruptive. |
| Remove a word (X button in Step A row) | No confirmation dialog. Immediate row removal. The action is easily reversible (user can start over with Cancel, or re-extract). |
| Uncheck a word (checkbox in Step A row) | No confirmation. The word is visually marked unchecked; it will not be committed. Trivially reversible by re-checking. |

**Note:** commit failures (per-card `saveCard` errors in Step B) are NOT destructive actions — they are non-fatal failures surfaced in the success summary. No "retry" confirmation is needed; the user sees the count and can manually re-add failed words.

## Validation Error Patterns

Identical inline pattern inherited from Phase 9/10. All Phase 11 errors use:

```tsx
<p className="text-sm text-destructive mt-1" role="alert">
  {errorCopy}
</p>
```

- Position: immediately below the relevant row or the commit button
- No toast, no banner, no dialog — inline only (matches Phase 9 D-08)
- Per-row translation failure: shown below the row's two inputs; does NOT block other rows
- Per-row commit failure: reflected in the success summary counts; NOT shown as inline errors during commit (surfaced post-commit in summary)
- Error clears: per-row translation error clears when the user edits either field in that row

## Accessibility Contract

Additions to Phase 9/10's accessibility contract:

| Requirement | Implementation |
|-------------|---------------|
| Checkbox labelling | Each checkbox gets `aria-label={`Keep "${word}"`}` — no visible label needed given the adjacent text input shows the word |

| X remove button | `aria-label={`Remove "${word}"`}` — icon-only button; aria-label is the minimum contract (same pattern as Phase 9 thumbnail clear button) |
| Translation row inputs | `id`+`htmlFor` pair on each Label+Input — same pattern as `TranslationForm`; ids must be unique per-row (use index suffix: `native-0`, `target-0`, etc.) |
| Per-row translation error | `role="alert"` on the error `<p>` — announced immediately on insertion without requiring focus (same pattern as Phase 10 extraction error) |
| Commit button in-flight | `aria-busy="true"` + `aria-label="Adding cards, please wait"` — mirrors Phase 10 extraction button pattern |
| Loader2 icons | `aria-hidden="true"` on all decorative spinners — the button label or status text carries the state |
| Success check icon | `aria-hidden="true"` — decorative; primary message `<p>` carries the content |
| Checkbox keyboard operability | Native `<input type="checkbox">` is fully keyboard operable by default; no additional `onKeyDown` needed |
| Focus management on step transition | No programmatic focus moves between Step A and Step B — user navigates naturally via Tab; appropriate for an in-page flow (same precedent as Phase 9 steps) |
| Already learned section | Non-interactive; `aria-label` not required — the section heading "Already learned" provides context; no role needed |

## Design Decisions Log

Decisions made during this UI-SPEC (auto mode — derived from 11-CONTEXT.md, 09-UI-SPEC.md, 10-UI-SPEC.md, and codebase):

| Decision | Choice | Rationale / Source |
|----------|--------|--------------------|
| Step A/B headings use `text-sm font-medium` not a heading element | `<p className="text-sm font-medium text-foreground">` | The review flow is a sub-section of the add-card page; a new `<h2>` would be semantically odd inside the existing `<h1 "Add a Card">` context. `font-medium` paragraph matches the Label weight, keeping visual hierarchy consistent without DOM heading semantics |
| Select-all/select-none style | `Button variant="ghost"` small controls | Ghost buttons are the correct weight for secondary controls that sit above a list; no accent consumption. Consistent with Phase 10 "Try again" as a recovery/secondary affordance |
| "Already learned" placement | Bottom of Step A, below new words | D-04 explicitly positions duplicates at the bottom. Visually: new words are the primary task; already-learned is informational context. Deliberate vertical ordering communicates hierarchy |
| Already learned row treatment | `line-through text-muted-foreground` + "already learned" tag | Strikethrough communicates "not actionable"; muted color communicates non-interactive. No checkbox, no input, no X. Matches D-04: marked, non-interactive, not committed |
| Translation fan-out spinner | Standalone `<Loader2>` + status text (not inside a button) | Translation is a batch fan-out across N words, not a single request — a button spinner would be semantically wrong. A standalone spinner with count copy communicates batch progress naturally. Analogous to Phase 10's button spinner for single-request extraction |
| Commit in-flight: Back + Cancel hidden | Both hidden (`display:none` / conditional) | Mirrors Phase 10 pattern (Back hidden during extraction). Writes are in-flight; navigating away mid-batch would produce partial writes with no summary. Hiding prevents this; the user must wait for summary |
| Commit in-flight: Translation inputs disabled | `disabled={true}` on all inputs | Communicates locked state — changes after click have no effect. Visual signal that the form is now processing |
| Per-row translation failure copy | "Translation unavailable — enter manually." | Exact same string as `TranslationForm`'s error copy (`translation-form.tsx` line 148). Direct reuse for consistency |
| Success summary format | Counts separated by ` · ` (interpunct) | Compact, readable, avoids comma-separated run-on. Consistent with common dashboard summary patterns (no existing precedent in codebase to deviate from) |
| Zero-added failure state | `variant="outline"` CTA + different copy | Primary accent is reserved for success-path actions. All-failed is a recoverable failure, not a success — outline correctly signals secondary action |
| `handleGoToDeck` navigation target | `/dashboard?deck={deckId}` | Phase 02 decision: URL params `?deck=id` for active deck state. This pre-selects the deck the user just added to, showing their new cards immediately |
| Font weight pair | 400 (regular) + 500 (medium) — not 400/600 | Inherits the Phase 9/10 locked decision. Pre-existing `text-xl font-semibold` heading is not modified |
| Spacing normalisation: `gap-3` → `gap-4` (checker revision 2026-05-19) | `gap-4` (16px) for translation list gaps | `gap-3` (12px) is not in the standard set {4,8,16,24,32,48,64}px. Normalised to nearest compliant value `gap-4` (16px), which gives appropriate breathing room between translation pairs and matches the outer word-list gap. Row-internal gaps remain `gap-2` (8px). |
| Spacing normalisation: `gap-1.5` / `py-1.5` → `gap-2` / `py-2` (checker revision 2026-05-19) | `gap-2` / `py-2` (8px) for AlreadyLearnedRow and section container | 6px values (`*-1.5`) are not multiples of 4 and not in the standard set. Normalised to `gap-2` / `py-2` (8px). |
| Typography normalisation: `text-xs` → `text-sm` (checker revision 2026-05-19) | `text-sm text-muted-foreground` for the "already learned" suffix tag | `text-xs` (12px) is not a declared type role. Normalised to `text-sm` (14px, body role) with `text-muted-foreground` to retain the visual de-emphasis. Keeps the strict 2-size (14px/20px) inherited system with zero new roles. |
