### Net-new — this phase (client state extensions within `ImageUploadFlow`)

No new component files required. All new states are rendered inline within the existing `Step 2` branch of `image-upload-flow.tsx`. The `useReducer` state machine gains new action types and state fields. No new `.tsx` files for UI components.

New reducer actions:

| Action | Trigger | State Change |
|--------|---------|--------------|
| `EXTRACT_START` | "Extract words" clicked | `extracting: true`, `extractError: null`, `extractWords: null` |
| `EXTRACT_SUCCESS` | 200 response with `words` array | `extracting: false`, `extractWords: string[]` |
| `EXTRACT_NO_WORDS` | 200 response with `words: []` | `extracting: false`, `extractWords: []` — treated as distinct display state |
| `EXTRACT_ERROR` | Non-2xx response | `extracting: false`, `extractError: { status: number; message: string }` |
| `EXTRACT_RETRY` | "Try again" clicked | Same as `EXTRACT_START` — resets error, preserves `file`/`previewUrl`/`selectedDeckId` |

New state fields on `ImageFlowState`:

```ts
extracting: boolean;          // true while the POST is in flight
extractError: { status: number; message: string } | null;
extractWords: string[] | null; // null = not yet extracted; [] = no-words result
```

## Interaction States

The following states apply to the **Step 2 deck-confirmation view** of `ImageUploadFlow`. Step 1 (pick/preview) is unchanged.

### State 0 — Idle (Phase 9 carry-forward)

The existing "Extract words" button as shipped in Phase 9. No change.

```
[recap thumbnail]
Label: "Add words to:"
DeckSwitcher
[← Back button]
[Extract words] — variant="default", w-full h-11
  disabled when file is null OR selectedDeckId is empty
  onClick → handleExtract()
```

### State 1 — In-flight / Loading (EXT-02)

Triggered by: user clicks "Extract words" with valid file + deck.

**"Extract words" button transforms in-place** — no layout shift, no separate loading overlay outside the button:

```
[recap thumbnail — unchanged, same max-h-32]
Label: "Add words to:" — unchanged
DeckSwitcher — unchanged, non-interactive (disabled prop or pointer-events-none during in-flight)
[← Back button — hidden during in-flight (remove from DOM / display:none)]
[Extract words button — variant="default", w-full h-11, disabled=true]
  Content: <Loader2 className="size-4 animate-spin mr-2" /> "Extracting words…"
```

**DeckSwitcher during in-flight:** render with `disabled` prop so the user cannot change deck mid-flight. Deck selection is preserved in state; it is restored to interactive on success/error.

**Back button during in-flight:** hidden. Removes the navigation affordance while a request is in flight; prevents the user from navigating away and leaving the request orphaned. Restores on success/error.

**No separate progress bar, toast, or overlay.** The button state communicates in-progress. The loading can take up to ~30s (D-13 timeout); the button's disabled+spinner state must persist for the full duration.

**Below-button status text (optional enhancement):**

```tsx
{state.extracting && (
  <p className="text-sm text-muted-foreground text-center">
    This can take up to 30 seconds…
  </p>
)}
```

Show this below the button only — it appears after ~3 seconds of in-flight time to reassure users the app has not frozen. If the executor judges this adds too much copy at small screen sizes, it may be omitted and the button spinner alone is sufficient. The copy string above is the canonical version if included.

### State 2 — Success / Words Returned (EXT-01 hand-off)

Phase 11 owns the editable review list. Phase 10 only needs to communicate "we got words" and hand off to Phase 11's entry point.

**Transitional success state** (rendered until Phase 11 is wired):

```
[recap thumbnail — unchanged, same max-h-32]
<p className="text-sm text-muted-foreground">
  Found {N} word{N !== 1 ? 's' : ''} — ready to review.
</p>
[Extract words button — variant="default", w-full h-11]
  Relabelled: "Review words →"
  disabled until Phase 11 wires the onReview prop/handler
  (Phase 11 replaces this button with navigation to the review screen)
```

**Word count display copy:** `"Found {N} word{plural}."` — always shows the exact count. This is the hand-off copy; Phase 11 replaces it with the review list header.

**Note for executor:** the success state should persist (not auto-navigate) so the user can see the count before Phase 11 is live. If `extractWords.length === 0` this state is NOT shown — fall through to State 3 (no-words).

### State 3 — No Words Found (EXT-03)

HTTP 200 with `{ words: [] }`.

```
[recap thumbnail — unchanged, same max-h-32]
<div className="flex flex-col items-center gap-3 py-4 text-center">
  <ImageOff className="size-8 text-muted-foreground" />   {/* optional — see Component Inventory */}
  <p className="text-sm font-medium text-foreground">
    No words found in this image.
  </p>
  <p className="text-sm text-muted-foreground">
    Try a photo with clearer text, or choose a different image.
  </p>
  <Button variant="outline" onClick={handleChooseDifferentImage}>
    Choose another image
  </Button>
</div>
[Extract words button — hidden in no-words state; replaced by "Choose another image" above]
```

`handleChooseDifferentImage` dispatches `BACK_TO_PICK` + `CLEAR_FILE` (or a new `RESET_TO_PICK` action that clears `extractWords` too) — returns the user to Step 1 empty state. Deck selection is preserved.

### State 4 — Error (EXT-04)

HTTP non-2xx. Error is shown **inline, below the DeckSwitcher**, preserving the recap thumbnail, deck selection, and Back button. The layout does not reset or navigate.

**Layout:**

```
[recap thumbnail — unchanged, same max-h-32]
Label: "Add words to:" — unchanged
DeckSwitcher — unchanged and interactive (user may want to try a different deck)
[← Back button — restored]
<p className="text-sm text-destructive mt-1">
  {friendlyErrorCopy(state.extractError.status)}
</p>
<div className="flex gap-2 mt-2">
  <Button variant="outline" onClick={handleExtractRetry}>
    Try again
  </Button>
</div>
[Extract words button — hidden while error is shown; "Try again" replaces it]
```

`handleExtractRetry` dispatches `EXTRACT_RETRY` (clears error, sets `extracting: true`) then re-calls the endpoint. The "Try again" button uses `variant="outline"` — not primary accent — to avoid reading as the new primary CTA.

**Error clears on:** successful retry (`EXTRACT_SUCCESS` or `EXTRACT_NO_WORDS`), or on `BACK_TO_PICK`.

### Loading / in-flight

|---------|------|

### Success (transitional — Phase 11 replaces)

| Element | Copy |
|---------|------|

### No words found (EXT-03)

| Element | Copy |
|---------|------|

| Secondary message | "Try a photo with clearer text, or choose a different image." |
| Affordance button | "Choose another image" |

### Errors — per HTTP status (EXT-04)

These are the exact friendly strings the client maps from `response.status`. The `friendlyErrorCopy(status)` helper returns one of these.

| HTTP Status | Scenario | Friendly Copy |
|-------------|----------|---------------|
| **429** | Rate limited | "You've made too many requests — please wait a moment and try again." |
| **413** | Image too large (server-side) | "That image is too large for the server to process. Please choose a smaller image (under 5MB)." |
| **415** | Unsupported image type (server-side) | "That file type isn't supported. Please choose a JPG, PNG, or WebP image." |
| **504** | Vision call timed out | "The extraction took too long and timed out. Please try again — it usually works on the second attempt." |
| **503** | Vision service not configured | "The word extraction feature isn't available right now. Please try again later." |
| **502** / **500** | Vision service error | "Something went wrong with the word extraction. Please try again." |
| **400** | Invalid request body | "There was a problem with the request. Please go back and choose a new image." |
| **401** | Not authenticated (rare — session expired) | "Your session has expired. Please refresh the page and try again." |
| Any other / network error | Unexpected failure | "Something went wrong. Please try again." |

**Copy rules:**
- Every error message ends with a clear next action (what to do).
- No technical jargon (HTTP codes, "502", "server error", "endpoint").
- Tone is friendly and non-blaming — consistent with LeoCards' casual tiger voice.
- "Please try again" is the closing instruction for recoverable errors.
- For non-recoverable or user-actionable errors (413, 415, 400), the instruction is "go back and choose" — directing to the correct action.
- 503 uses "isn't available right now" — acknowledges a configuration issue without exposing it.

### Destructive actions

No destructive actions are introduced in Phase 10. The "Choose another image" affordance in the no-words state dispatches `BACK_TO_PICK` — this clears the extraction result but not the file (file is cleared separately by `CLEAR_FILE` if the user proceeds back to Step 1 empty). No confirmation dialog required; the action is low-stakes and the image is not uploaded/stored anywhere.

## Validation Error Patterns

Inherited from Phase 9. All extraction errors use the **same inline pattern**:

```tsx
{state.extractError && (
  <p className="text-sm text-destructive mt-1">
    {friendlyErrorCopy(state.extractError.status)}
  </p>
)}
```

- Position: immediately below the DeckSwitcher, above the "Try again" button
- No toast, no banner, no dialog — inline only (matches Phase 9 D-08)
- Error clears on retry dispatch or on `BACK_TO_PICK`
- Error does NOT clear on deck change — user can change deck and then hit "Try again"

## Accessibility Contract

Additions to Phase 9's accessibility contract:

| Requirement | Implementation |
|-------------|---------------|
| Loading button announcement | `aria-busy="true"` on the button during in-flight state; additionally `aria-label="Extracting words, please wait"` to override the icon+text label for screen readers |
| Spinner icon accessibility | `<Loader2 aria-hidden="true" />` — decorative; the button label carries the state |
| Error announcement | Inline `<p className="text-sm text-destructive">` is in natural reading order. For screen readers, add `role="alert"` to the error paragraph so it is announced immediately on insertion without requiring focus |
| "Try again" button | Descriptive label is sufficient: `aria-label="Try again"` — no additional context needed given its visual proximity to the error |
| No-words state | The no-words container is in natural reading order; no `aria-live` needed. "Choose another image" button label is self-describing |
| DeckSwitcher disabled state | Passes `disabled` prop to the underlying Radix Select — screen reader announces as disabled/unavailable |
| Double-submit prevention | `disabled={state.extracting}` on the button — `disabled:pointer-events-none` (from `buttonVariants`) prevents any click; no additional `aria-disabled` needed (native `disabled` is sufficient for Base UI Button) |

## Design Decisions Log

Decisions made during this UI-SPEC (auto mode — derived from 10-CONTEXT.md, 10-AI-SPEC.md, 09-UI-SPEC.md, and codebase):

| Decision | Choice | Rationale / Source |
|----------|--------|--------------------|
| Loading indicator placement | Inline button transformation (spinner + relabelled text), no separate overlay | Matches Phase 9's "skeleton shimmer replaces input during in-flight translation" pattern (STATE.md Phase 02 decision); avoids layout shift; button retains `h-11` to prevent reflow |
| Spinner color | `text-primary` (accent orange) | Accent already reserved for "Extract words" CTA; spinner is a continuation of that affordance, not a new accent use |
| Back button hidden during in-flight | Hidden (`display:none` or conditional render) | Prevents navigation away while a costly vision request is in flight; consistent with D-15 double-submit intent |
| DeckSwitcher disabled during in-flight | `disabled` prop | Prevents a deck change that would be ignored by the in-flight request; restores on resolution |
| Below-button hint copy ("up to 30 seconds") | Optional — executor may omit | 30s is unusually long for a web action; the hint prevents abandonment. Marked optional to avoid over-speccing a low-stakes decision |
| Error copy strategy | Per-status strings, no generic fallback except the final catch-all | 10-CONTEXT.md D-14 explicitly keys client UI off HTTP status; per-status friendly copy is the full deliverable this spec owns |
| "Try again" affordance style | `variant="outline"` (not `variant="default"`) | Primary accent is reserved for the "Extract words" CTA; "Try again" is a recovery action, not the primary intent |
| No-words "Choose another image" | Dispatches `BACK_TO_PICK` + `CLEAR_FILE` | D-16 says preserve `file`+`previewUrl`+`selectedDeckId` on errors; but "no words" is a user-initiated "try a different image" — clearing the file is the correct intent. Deck selection is preserved. |
| Success state copy | "Found {N} word(s) — ready to review." with "Review words →" button | Phase 11 owns the review UI; this is a deliberate stub. The copy is forward-looking (names Phase 11's action) so the user knows what happens next |
| 401 error copy | "Your session has expired. Please refresh the page and try again." | Not listed in D-14's status map (which assumes auth is always valid at this point), but defensive inclusion prevents a blank/generic error for session-expiry edge case |
