## Architectural learnings (recorded for Phase 999.1)

1. **`dynamic({ssr: false})` boundaries hide LCP candidates.** A poster `<Image>` inside a client-only dynamic import doesn't render in SSR HTML, so the browser has no early LCP candidate. Always render the LCP candidate in the SSR-renderable parent.
2. **`<motion.div initial={{opacity: 0}}>` disqualifies elements as LCP candidates** at SSR time. Wrap fade-ins around non-LCP content only.
3. **`/_next/image` proxy adds ~100–300 ms cold-start latency.** For already-optimized webps that don't need responsive variants, serve direct from CDN.
4. **Lighthouse mobile-simulation variance is huge.** A 2× run-to-run LCP spread is normal on Vercel previews under Slow 4G + 4× CPU throttle. Don't chase the median below the gate; use real-user CWV (CrUX, Vercel Analytics) as the source of truth post-ship.
5. **`requestIdleCallback` fires inside Lighthouse trace windows.** It's not "post-LCP" for lab measurement purposes. Gesture-only is the right deferral primitive.
6. **`three` r160 tree-shake yields 0 bytes** under Turbopack — monolithic ESM with internal cross-refs. Real shrink needs r170+ subpath exports.
