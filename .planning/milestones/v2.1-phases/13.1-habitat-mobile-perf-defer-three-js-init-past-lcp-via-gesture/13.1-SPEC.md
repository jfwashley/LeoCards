# Phase 13.1: habitat-mobile-perf — Specification

**Created:** 2026-05-27
**Ambiguity score:** 0.103 (gate: ≤ 0.20)
**Requirements:** 8 locked
**Supersedes:** Phase 13.1 attempt #1 (reverted; postmortem at `13-PERF-FIX-ATTEMPT-1.md`)
**Closes:** Phase 13 carried regression R9 (`/habitat` mobile CWV FAIL)

## Goal

Bring `/habitat` mobile back into CWV "Good" by deferring Three.js init past LCP using a full-resolution static poster as the LCP element and a gesture-only canvas mount. No tree-shake, no mobile-budget knobs — those produced no measurable benefit in attempt #1 and are explicitly out of scope.

## Background

**Current state (post-revert, commit `b962c35`):**
- `/habitat` mobile median CWV (Lighthouse 13.3.0 vs Vercel preview, 3 runs, see `13-PERF-REAL.md`): LCP **2989 ms** (gate ≤ 2500), TBT **646 ms** (gate ≤ 200), CLS 0, Perf 77. **R9 FAIL.**
- Three.js 504 KB code-split chunk parses on mount under mobile 4× CPU throttle; dominates main-thread time.
- All other CWV cells (`/dashboard` desktop+mobile, `/habitat` desktop) PASS.
- `src/components/habitat-3d-canvas.tsx` mounts the live Three.js scene immediately on page load via `dynamic({ ssr: false })`.
- `public/habitat/widget-l{1..9}.webp` exist but are 1–3 KB widget-sized images, NOT usable as `/habitat` LCP element (Plan 13.1 attempt #1's fatal mistake).

**What attempt #1 got wrong (locked findings from postmortem):**
1. Widget-sized posters reused as hero LCP elements → did not qualify as LCP candidate; Lighthouse failed to identify an LCP element on one run.
2. `requestIdleCallback` defer fired inside Lighthouse's ~10s trace window → canvas mounted during trace → TBT *increased* to 1061 ms.
3. three r160 tree-shake produced 0 bytes savings (monolithic ESM).
4. Bundling three opts in one PR made root-cause attribution impossible.

This phase corrects all four.

## Requirements

### R1. Full-resolution `/habitat` posters generated at build time
- **Current:** No `/habitat`-sized posters exist. `widget-l*.webp` are 1–3 KB widget assets.
- **Target:** 9 webp files at `public/habitat/hero-l{1..9}.webp`, rendered at the actual `/habitat` canvas viewport (mobile-first: 720×405 minimum, or 1280×720 at 16:9 to match the wrapper's `aspectRatio: "16/9"`), each 20–100 KB. Generated via a Playwright build-time script analogous to Plan 06's hero-image generator but at full resolution. Script lives at `scripts/render-habitat-posters.mjs` (or equivalent) and is invokable via `npm run posters:habitat`.
- **Acceptance:**
  - [ ] `ls -la public/habitat/hero-l*.webp` shows 9 files, each between 20 KB and 100 KB
  - [ ] Each poster's image dimensions ≥ 720×405 verified via `sharp` metadata check
  - [ ] Posters depict the same scene the live canvas would render at the same level/theta — verified by manual visual inspection of `hero-l5.webp` matching a fresh canvas screenshot at level 5

### R2. Static poster is the LCP element on `/habitat`
- **Current:** No poster on `/habitat`. The LCP candidate is whatever Three.js paints first (typically the canvas after Three.js parse + scene build).
- **Target:** The `/habitat` page renders `public/habitat/hero-l{N}.webp` (N = current `HabitatState.level`) via `next/image` with `priority` set, sized to the canvas wrapper, BEFORE any Three.js code is loaded. The poster IS the LCP candidate per Chrome's LCP algorithm.
- **Acceptance:**
  - [ ] Lighthouse JSON `largest-contentful-paint-element.details.items[0].node` references the poster image element on `/habitat` mobile + desktop
  - [ ] Network waterfall shows the poster requested in the initial HTML parse, before any chunk containing `WebGLRenderer`
  - [ ] `priority` prop set on `next/image`; no invalid props (e.g. `preload`)

### R3. Three.js canvas mounts ONLY on user gesture
- **Current:** Canvas mounts immediately on component mount via `useEffect`.
- **Target:** Canvas mount is gated on first user gesture (`pointerdown` | `touchstart` | `keydown` | `wheel` | `scroll` on the page). No idle callback fallback. No timer fallback. If the user never interacts, the canvas never mounts. This is intentional and is the price of CWV pass.
- **Acceptance:**
  - [ ] Unit test: rendering the component without any event dispatch leaves `canvasMounted === false` indefinitely
  - [ ] Unit test: dispatching `pointerdown` on the page sets `canvasMounted === true` within one tick
  - [ ] Unit test: dispatching `keydown` (any key, on document or wrapper) triggers the mount
  - [ ] Unit test: `scroll` event triggers the mount
  - [ ] Code search: `grep -n "requestIdleCallback\|setTimeout.*[Mm]ount" src/components/habitat-3d-canvas.tsx` returns 0 matches in the gate logic

### R4. Reduced-motion users never mount the canvas
- **Current:** Reduced-motion behavior is Plan 04's ambient/auto-orbit freeze inside the live canvas.
- **Target:** When `prefers-reduced-motion: reduce` is detected, the canvas NEVER mounts for the entire session, regardless of gesture. The poster IS the experience. Applies on all form factors (mobile + desktop), not just mobile — strict honor of the OS preference.
- **Acceptance:**
  - [ ] Unit test: `matchMedia('(prefers-reduced-motion: reduce)')` returning `matches: true` prevents canvas mount even after gesture
  - [ ] No keyboard-orbit affordance shown to reduced-motion users (no `tabIndex`, no aria-label suggesting interactivity beyond the poster)

### R5. Canvas-mount UX affordance — subtle "Tap to animate" hint
- **Current:** No affordance.
- **Target:** A subtle "Tap to animate" (or play-icon) overlay fades in 2000 ms after the poster paints if no gesture has been detected. Fades out instantly on first gesture or canvas mount. Not shown to reduced-motion users.
- **Acceptance:**
  - [ ] Unit test: 2.0 s after mount with no gesture, the hint element is in the DOM with opacity > 0
  - [ ] Unit test: first gesture event removes / hides the hint
  - [ ] Unit test: reduced-motion path never renders the hint
  - [ ] Hint copy is one short sentence (≤ 25 chars), localizable

### R6. Zero CLS on canvas swap-in
- **Current:** N/A (no swap).
- **Target:** When the canvas mounts and the poster fades out, the layout shift score for the swap is 0. Achieved by sizing the canvas container with `aspectRatio` + `maxHeight` BEFORE either child paints, with both poster and canvas absolutely positioned within.
- **Acceptance:**
  - [ ] Lighthouse `cumulative-layout-shift.numericValue === 0` on `/habitat` mobile + desktop after a Playwright-driven gesture mount
  - [ ] Playwright spec: capture two screenshots (before-gesture and 500 ms after-gesture); assert pixel positions of the wrapper bounding-box are unchanged

### R7. CWV "Good" on `/habitat` mobile + desktop
- **Current:** `/habitat` mobile LCP 2989 ms / TBT 646 ms (FAIL). `/habitat` desktop PASS.
- **Target:** Median over 3 Lighthouse runs against the Vercel preview with the same auth-cookie + bypass-header setup as `13-PERF-REAL.md`:
  - `/habitat` mobile: LCP ≤ **2500 ms**, TBT ≤ **200 ms**, CLS ≤ **0.1**, Perf score ≥ **80**
  - `/habitat` desktop: LCP ≤ **2500 ms**, TBT ≤ **200 ms**, CLS ≤ **0.1**, Perf score ≥ **90** (desktop baseline was 931/19/0/98 — should not regress)
- **Acceptance:**
  - [ ] 3 Lighthouse runs/cell committed at `.planning/phases/13.1-*/lighthouse-postfix-2/`; medians written to a `13.1-PERF.md` table
  - [ ] All four thresholds above pass on the median

### R8. `/dashboard` CWV does not regress
- **Current:** `/dashboard` mobile LCP 2151 / TBT 286 / Perf 93; desktop LCP 985 / TBT 36 / Perf 98.
- **Target:** Same Lighthouse setup; medians must not regress more than 10% on LCP or TBT relative to the `13-PERF-REAL.md` baseline. No `/dashboard` code is touched in this phase.
- **Acceptance:**
  - [ ] 3 Lighthouse runs/profile for `/dashboard` committed; medians written to the same `13.1-PERF.md`
  - [ ] `/dashboard` mobile median LCP ≤ 2367 (2151 × 1.10), TBT ≤ 315 (286 × 1.10)
  - [ ] `/dashboard` desktop median LCP ≤ 1084 (985 × 1.10), TBT ≤ 100 (free margin given absolute floor)
  - [ ] Manual `git diff --stat` confirms no changes under `src/app/dashboard*` or `src/components/habitat-widget*`

## Boundaries

### In scope
- `src/components/habitat-3d-canvas.tsx` (modified — adds poster + gesture gate + hint)
- A new poster-generation script (`scripts/render-habitat-posters.mjs` or equivalent), one-time use
- `public/habitat/hero-l{1..9}.webp` (9 new asset files)
- Unit tests covering R3/R4/R5
- A Playwright spec covering R3 gesture mount + R6 zero-CLS
- A `13.1-PERF.md` capturing the post-fix Lighthouse measurements

### Out of scope (explicit non-goals, with reasoning)
- **`three.js` tree-shaking** — attempt #1 proved r160 yields 0 bytes savings; deferred until three publishes proper sub-path exports (r170+) or to Phase 999.1.
- **Mobile-budget knobs** (skip elephant, toonGrad cache, lower `Q` on slow CPU) — attempt #1 produced no measurable benefit and added complexity. If R7 still fails after R1-R6 land, these become candidates for a Phase 13.2 follow-up.
- **`/dashboard` perf changes** — already PASS baseline; touching it risks regression. R8 only verifies non-regression.
- **Live widget restoration on `/dashboard`** — D-28 cached decision stays; not revisited.
- **PixiJS code paths** — all removed in Plan 13-06; out of scope.
- **Three.js version bump (r160 → r170+)** — much larger change; would have its own phase if undertaken.
- **General app-wide perf** (other routes' CWV, RSC waterfalls, prefetch tuning) — that's Phase 999.1 territory.

## Constraints

- **Renderer locked** to `three@0.160.x` (Phase 13 R2; no version bump in this phase).
- **No regression** in any of the 9 acceptance gates that Phase 13 passed (R1-R8, R10): scene fidelity, keyboard orbit, mood/decay, reduced-motion behavior of the *canvas*, PixiJS absence.
- **No new dependencies** unless a poster-generation script needs a single dev-dep (existing `sharp` + `playwright` should suffice).
- **Same Lighthouse setup as `13-PERF-REAL.md`** for apples-to-apples: Lighthouse 13.3.0, `--form-factor=mobile --throttling-method=simulate` for mobile cells, `--preset=desktop` for desktop, 3 runs per cell with cold + warm cache mixed, headers carry both the `__Secure-better-auth.session_token` cookie and `x-vercel-protection-bypass` header against a fresh Vercel preview deploy.
- **Atomic commits per requirement cluster** (e.g. one commit for poster generation, one for canvas gating, one for hint UX, one for measurements + perf doc).
- **One PR worth of work** — must be reviewable and revertable as a unit.
