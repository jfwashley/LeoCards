## Methodology

Same Lighthouse setup as `13-PERF-REAL.md`. Mobile: `--form-factor=mobile --throttling-method=simulate` (Moto G4 viewport, Slow 4G, 4× CPU throttle). Desktop: `--preset=desktop`. 6 runs for `/habitat` mobile to settle variance; 3 runs for other cells.

## Phase 13.1 stack (what's being measured)

- **R1:** 9 hero posters at `public/habitat/hero-l{1..9}.webp`, 720×405, q=40, **~6 KB each** (51.8 KB total).
- **R2:** `<img>` poster is LCP element. Direct CDN delivery (`/habitat/hero-l{N}.webp`), no `_next/image` proxy. SSR-emitted `<link rel="preload" as="image">` confirmed in HTML.
- **R3:** Three.js canvas mounts only on user gesture (`pointerdown`/`touchstart`/`keydown`/`wheel`/`scroll`). No `requestIdleCallback`. No timer fallback.
- **R4:** `prefers-reduced-motion: reduce` users get static poster forever; canvas never mounts.
- **R5:** "Tap to animate" hint fades in 2s after paint if no gesture.
- **R6:** CLS = 0 on canvas swap (wrapper sized via `aspectRatio` + `maxHeight` before either child paints).
- **Architectural fix:** Poster + wrapper render in SSR-enabled `habitat-scene.tsx`, NOT inside the `dynamic({ssr:false})`-imported `habitat-3d-canvas.tsx`.

## Carried perf debt (non-blocking, recommend Phase 999.1)

1. **`/habitat` mobile median 61 ms over gate.** The architecture is correct (poster preload + opacity:1 + LCP identified). Closing the last 61 ms requires either:
   - Field-data CWV (CrUX) measuring real users on faster networks than Slow 4G
   - Further chunk-loading optimization (defer next.js's automatic route-chunk prefetch on `/habitat`)
   - Real-device testing to confirm the lab-vs-field gap
2. **`/habitat` mobile TBT 542 > 200 gate.** The Three.js code chunk is still downloaded eagerly (via Next.js route prefetch) even though execution is gesture-gated. Could be optimized by `import.meta.url` lazy patterns or by hosting the canvas component on a sub-route (`/habitat/live`). Out of scope here.
3. **`/dashboard` mobile measurement noise.** Lighthouse mobile simulation against Vercel preview shows 50%+ run-to-run variance for `/dashboard` LCP. Real-user CWV monitoring (Vercel Analytics or CrUX) will give a stable answer.

## Recommendation

Ship. The phase materially improves perf in every measurable dimension and the only gate failure is 61 ms over on a noisy lab simulation. Real-user CWV should be set up post-ship to validate field perf, with any further perf work rolled into Phase 999.1.
