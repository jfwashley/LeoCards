## Mount-isolation evidence (no premature canvas mount)

Test H6 (the "hint must not trigger the mount" pin) walks the `setupHintTimer` function body in the source and asserts:

```
expect(body).not.toMatch(/setGestured/);
expect(body).not.toMatch(/setCanvasMounted/);
expect(body).not.toMatch(/mountHabitatScene/);
```

The factory body is verifiably visibility-only:

```ts
export function setupHintTimer(opts: SetupHintTimerOpts): () => void {
  const { reducedMotion, canvasMounted, delayMs, setHintVisible } = opts;
  if (reducedMotion) return () => {};
  if (canvasMounted) return () => {};
  const id = setTimeout(() => { setHintVisible(true); }, delayMs);
  return () => { clearTimeout(id); };
}
```

The setTimeout callback flips ONLY `setHintVisible`. The canvas-mount path (`setGestured(true)` → `canvasMounted = true`) lives exclusively in the Plan 02 gesture-gate effect and is unchanged by this plan.

## Reduced-motion suppression evidence

Three layers, all defensive:

1. **Factory short-circuit (Test H4):** `setupHintTimer({reducedMotion: true, ...})` returns a no-op cleanup before calling `setTimeout`. After 10 s of fake time, `setHintVisible` is not called.
2. **JSX guard (Test H7):** the overlay's render condition is `{!reducedMotion && hintVisible && !canvasMounted && ...}`. Even if `hintVisible` somehow flipped true, reduced-motion users would still see nothing.
3. **State stays `false`:** because layer 1 never schedules the timer, `hintVisible` is never set true for reduced-motion users — so layer 2 is never even consulted.

## CLS impact

Zero. The overlay is `position: absolute` inside the wrapper that already carries intrinsic size from Plan 02 (`aspectRatio: 16/9` + `maxHeight: min(70vh, 400px)`). The pill paints in the wrapper's existing positioning context; no reflow, no layout shift, no margin/padding contribution to the wrapper's box.

## A11y posture

- `aria-hidden="true"` on the overlay — the static poster already has `role="img"` + `aria-label="Tiger habitat level N"`, which labels the scene. Adding a second label would be redundant and would imply interactivity that reduced-motion / AT users cannot exercise (R4 forbids that).
- `pointerEvents: "none"` — the gesture that dismisses the hint passes straight through the overlay to the document, where the Plan 02 gesture gate captures it. The hint is purely cosmetic.
- Reduced-motion users never see the hint (factory short-circuit + JSX guard).

## Deviations from plan

- **Test file extension `.ts` not `.tsx`.** Repo Vitest is `environment: "node"` (no jsdom), same constraint Plan 02 hit (its `setupGestureGate` test is also `.ts`). The plan's behaviors (H1–H6) are covered via the pure factory + source-grep pattern; I additionally added H7 (JSX shape) and H8 (constant referenced in JSX) so the React-shell wiring is also pinned without RTL. Equivalent acceptance coverage, lower test-setup cost.
- **No i18n wrapper around `HINT_COPY`.** Plan accepts this: "use whatever i18n pattern is already in the codebase; if none, plain string is fine — note in SUMMARY." Grep for `next-intl`, `react-i18next`, `formatjs`, `i18n` in repo returns nothing wired up. Constant is exported so a future localization PR can wrap one symbol.
- **Cleanup-in-effect for `canvasMounted=true`.** Plan suggests the effect resolves both "schedule" and "clear when mounted" in one body. I split: when `canvasMounted` is true I explicitly call `setHintVisible(false)` then return (no factory call). When false, I delegate to `setupHintTimer` which itself short-circuits if needed. Functionally identical, but it makes the "canvas just mounted → hide the hint NOW, not at the next render" path explicit and avoids relying on the JSX guard alone to hide the overlay if `hintVisible` was already true at the moment of mount.
